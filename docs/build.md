# Build reproduzível (fase 3)

## Resultado

Todos os 23 módulos (`BOOT` + 22 gmodules) são reconstruídos **byte a byte** a partir do split do splat (`make check-all`). Código já em C compilado pelo compilador original e linkado no lugar exato: `libhtml_view` (2 funções) e, no `BOOT`, `src/BOOT/ehfile.c` (VFS, 29 funções, 0x0882ECAC–0x0882FC3C) `src/BOOT/modmgr.c` (gerenciador de módulos + espera de frame + menu de depuração, 19 funções, 0x08859044–0x08859824, com a tabela estática de módulos em `.data`) `src/BOOT/sys.c` (thread de cenas `ehscript`, `sys_init`, pilha de estados, 17 funções, 0x0883CEB0–0x0883D708) e `src/BOOT/main.c` (`main`, laço de frame, reset, overlay de loading, acessores dos globais do jogo, 27 funções, 0x0883DD58–0x0883E670, com `dir_table`/`game_module_table`/`sys_config` em `.data`).

## Compilador

- Binário: `mwccpsp.exe` **3.0.1 build 219** (`tools/ext/mwccpsp_219/`, da coleção do decomp.me), executado com `wibo` 1.1.0. O `.comment` dos módulos diz "MW MIPS C Compiler (2.4.1.01)", mas esse texto é o do front-end e é igual em todos os builds 3.0.1; o build 219 gera código idêntico nas funções testadas e o build 121 não (4 palavras diferentes em `save_path_build`).
- Flags confirmadas: **`-O4,p -sdatathreshold 0`**. `-O4,s` bate nas funções sem laço mas não em `ehfile_busy` (0x0882F468): com `,s` o laço indexa (`sll`+`addu`), com `,p` incrementa o ponteiro como no original. `-O2` não bate.
- Include path: `-i include` (o `-I` do mwcc exige `-Ipath` sem espaço).
- Strings literais vão para `.data` por padrão (o módulo original não tem `.rodata`); jump tables saem em `.rodata` do objeto. Nos gmodules o linker original as fundia no `.data` logo após o `.data` do mesmo objeto (`fix_ld.py` reproduz isso por padrão). No BOOT todas as `.rodata` dos objetos vêm **antes** de todos os `.data` (região 0x08872F50–0x088EB0xx, 129 jump tables): o `.c` declara `// @rodata 0xA-0xB`, `splat_config.py` emite um subsegmento `.data` chamado `<arq>__rodata` e `fix_ld.py` o troca por `<arq>.c.o(.rodata)` naquela posição (`deck.c`).
- Headers em `include/`: `psp.h` (protótipos sce* usados, tipos Sce*), `libc.h` (MSL), `ehfile.h` (tipos do subsistema). Sem headers da MSL no pacote: `sceIoLseek` é declarado devolvendo `int` porque o código original só testa `$v0`.
- O mwcc emite **uma seção `.text` por função** e **uma `.data` por literal**; `mwcc_check.py` localiza a função pela seção do símbolo. Literais idênticos de um mesmo `.c` são unificados (o `""` do nome da thread e do FPL).

## O que o mwccpsp faz com o fonte (aprendido no `ehfile`)

Cada item custou tentativas; vale consultar antes de brigar com uma função.

- **Base de struct em registrador salvo:** `EhfileState *s = &ehfile_state;` faz o compilador materializar `lui/addiu` em `$sN` e acessar `0x40C($s1)`; acesso direto `ehfile_state.campo` vira `lui/lw %lo(sym+off)`. O original mistura os dois estilos por função (ver `ehfile_read_async` vs `ehfile_init`).
- **`T *const p = &g;`** impede a propagação da constante no primeiro acesso: só assim `ehfile_term` carrega `0x410($s0)` antes do primeiro `blezl`. Ponteiro simples dobra o primeiro acesso em `lui/lw` direto.
- **Ordem de declaração dos locais** decide a atribuição de `$s0..$s7` e a posição na pilha (`ehfile_get_size`: `st, path, size`; `ehfile_build_lbn_table`: `pvd, ptab, ptab_size, ptab_lbn, fd`). `tools/perm_decls.py` testa todas as permutações contra os bytes originais.
- **Stores a campos distintos são reordenados** pelo escalonador: a ordem no fonte que bate pode ser diferente da ordem dos `sw` (`names_end` antes de `table_end`/`table`).
- **`if (x)` materializa booleano** (`sltu`/`xori`) quando `x` é um valor carregado; `== 0` em resultado de chamada vira `beqz` direto. `break`/`return` dentro de laço mudam o lado do desvio; `do { } while (cond)` com `break` reproduz os laços de retry.
- **`switch` emite os testes em ordem inversa à dos `case`** e os corpos na ordem do fonte (`ehfile_thread`: `case 0` antes de `case 1`; `modmgr_load_ex`: `case -1` escrito primeiro para ser testado por último). Um `if`/`else if` com dois valores também pode ser um `switch` no original (`modmgr_init`).
- **Tail call:** `return f(...)` com os mesmos argumentos vira `j f` (os aliases de exportação `ehfile_*_alias`, `ehfile_close`).
- **Acesso desalinhado:** struct com `#pragma pack(1)` gera `lwl/lwr` (registro de diretório ISO9660).
- **Intrínsecos Allegrex:** `max`/`min`/`ins`/`ext` (e `clz`, `seb`, `rotr`, `bitrev`, `sqrt_s`…) só saem de `__builtin_allegrex_*`; nenhuma forma em C puro gera essas instruções (união de bitfields vai para a pilha, `a > b ? a : b` vira `slt`/`beqzl`). `include/allegrex.h` define `ALLEGREX_MAX/MIN/INS/EXT` com fallback em C para o port. Lista completa: `strings mwccpsp.exe | grep __builtin_allegrex`. O mwcc também aceita funções `asm tipo f(args) { ... }` como último recurso.
- Expressões booleanas: `!p` gera `sltu v0,zero,p; xori 1`; `p == 0` gera `xor; sltiu 1`. A ordem das instruções independentes no prólogo segue a ordem dos statements no fonte.
- `*p++ = *q++` incrementa `q` antes de `p`; o original (`menu_count_lines`) tem `p++` antes de `q++`, isto é, foi escrito como `*p = *q; p++; q++;`.
- `return x` logo após `x = f()` reaproveita `$v0` (sem `move`): `if (id <= 0) return id;` bate onde `if (id > 0) {...} return id;` não.
- Função que no original não escreve `$v0` antes de voltar é `void` (um `int f(void)` com `return 1;` muda a alocação de registradores mesmo onde o `li v0,1` some).
- `asm { addi $v0, $ra, 0 }` dentro de uma função C reproduz instruções soltas do original (`ehscript_set_static` tem um `addi` sem efeito).
- Comparação com constante: `x >= 0x20F580` bate onde `x > 0x20F57F` troca os registradores (`$at`).
- Ordem de avaliação: `SysSave *s = sysstate_get(); s->flags |= 1 << bit;` carrega a máscara depois da chamada; `sysstate_get()->flags |= 1 << bit` calcula a máscara antes e a guarda em `$s0`.
- `f(x = g())` faz o argumento sair de `$v0` em vez do registrador da variável.
- **Caudas idênticas são fundidas:** um `switch` em que cada `case` faz o mesmo store com índice diferente vira uma cadeia `beql` com o `addiu` no delay slot e um bloco comum, e os corpos originais ficam como código morto (`stat_event_record`, 616 B dos quais 264 mortos). Escrever `kind += N; break;` + store comum gera o código sem os blocos mortos (não bate).
- Fallthrough entre `case`s não adjacentes no fonte: `goto` para um rótulo dentro do `case` seguinte (`ehscript_thread`, 3→5 com `case 4: break;` no meio) bate; mover o `case 4` muda a ordem dos testes.
- **Registrador do resultado de comparação com constante:** `x < c`, `x > c` e `x <= c` saem em `$at` (`slti $at`); `x >= c` sai em um temporário (`slti $v0`/`$v1`). Semanticamente iguais, bytes diferentes: `if (n >= 5)` vs `if (n > 4)` (`deck_slot_set_level`), `do {} while (i <= 0x4A)` vs `< 0x4B` (`req_flags_any`), `if (v > 8000) … else …` vs `v >= 0x1F41` (`deck_slot_set_value`), `if (v >= 2) { … } return 0;` vs `if (v < 2) return 0;` (`value_to_tier`).
- Tipo de retorno `int` em getters de `unsigned short`: o chamador original compara `$v0` direto (sem `andi 0xFFFF`) em `deck_slot_get_level`/`req_flag_get`; declarar o retorno `int` bate nos dois lados.
- `p[i + 0x97D0]` com `unsigned char *p = (unsigned char *)s` gera `addu; lui 1; lbu -0x6830(...)`; `s->byte_97d0[i]` gera `addiu 0x7FFF; addiu 0x17D1` (`sysstate_get_byte_97d0`), mas no setter vizinho é o acesso por campo que bate (`sysstate_max_byte_97d0`).
- Ordem das funções no objeto = ordem das **definições** no fonte (`static` usadas antes de definidas precisam de protótipo: `state_noop_*` ficam depois de `sys_state_set_default_callbacks`). `check_file.py` não detecta isso; só o `make check`.
- Variável `unsigned short` ou `int` para laço com `lhu`: `int bestv` + indexação `d[i].value` bate em `deck_find_best_slot`; ponteiro incrementado troca `$a0`/`$a2`.
- **`while (*s)` vs `while (*s != 0)`:** com `!= 0` o valor carregado fica vivo no laço (um `lhu` por iteração, em `$a2`); com `while (*p)` sobre uma **cópia local do ponteiro** (`const u16 *p = s;`) o compilador recarrega `*p` a cada iteração em `$v1`, como o original de `wcschr_index`. `while (*s)` sem cópia gera `andi v1,v1,0xFFFF` no lugar da recarga.
- **Máscara de argumento `unsigned short`:** o chamador faz `andi a0,x,0xFFFF` só se o protótipo visível declara o parâmetro `unsigned short`; função sem protótipo (declaração implícita) ou com parâmetro `int` passa o registrador direto (`inv_get_state` em `inv_collection_permille`). Protótipos em `include/game.h` devem copiar a assinatura da definição.
- `if (flag) { A } else { B }` gera `beql flag==0 → B` com A em sequência; a ordem dos ramos no fonte é a ordem no binário (`partner_table_lookup`).
- Tabelas de dados inicializadas (`static T tab[N] = {...}`) saem uma seção `.data` por objeto, alinhadas a 4, na ordem das definições; `const` não é necessário (o original as tem em `.data`). As de `wstr.c` foram geradas a partir dos bytes do ELF.
- `*p++ = *s++` em ramo `if/else` com `p++` duplicado nos dois ramos (`wcsncpy`): o original tem o `addiu p` em cada ramo, isto é, `if (*s == 0) { *p = 0; p++; } else { *p = *s; s++; p++; }`.
- **Laços desenrolados ×8** (`wstr_reverse`, cópias e preenchimentos de `wsprintf`, `wfmt_float_digits`): são obra do `-O4,p`; um `for` simples reproduz o desenrolamento e o laço de resto. `s[n - i - 1]` (não `s[n - 1 - i]`) dobra o `-1` no offset do `lhu`.
- **Varargs:** `include/stdarg.h` próprio. `va_start` = `__builtin_next_arg(parm) - ((__builtin_args_info(2) >= 8) ? 0 : (8 - __builtin_args_info(2)) * 4)` (não dobra a constante, como o original: `li v1,2; slti v0,v1,8 …`); `va_arg` avança o ponteiro (alinhando a 8 para `double`) e lê em `ap - sizeof`. `(float)double` chama `__truncdfsf2` (nomes libgcc no runtime da MSL). `(k >> 1) & 1` gera `ext` sem builtin.
- `build/shape_diff.py SRC FUNC ADDR [--regs]`: diff estrutural ignorando nomes de registradores; útil para separar forma de alocação (`wsprintf`: forma igual, alocação diferente — fica em `@asm`).
- **Soma de cadeia com variável:** `*w = -2 - a - b - c + d->w` gera `addu w, soma`; o original tem `addu soma, w`, que só sai com a cadeia numa variável local: `t = -2 - a - b - c; *w = t + d->w;` (`menu_item_rect`, `menu_cursor_y`). Operandos "variável + variável" saem na ordem do fonte; "expressão + variável" é reordenado.
- Conversão u16→float: `(float)(int)(unsigned short)w` gera `andi; mtc1; cvt.s.w`; `(float)(unsigned short)w` gera a sequência de unsigned→float com `bltz` (`menu_cursor_y`).
- Getters com índice: `if (i != -1) { ...; return 1; } return 0;` bate (`beql i == -1 → fim` com o `0` no delay slot); `if (i == -1) return 0;` não (`menu_item_open`, `menu_remove_item`, `menu_item_state`).
- Constantes `const` globais e strings de `const char []` vão para `.rodata` (uma seção por objeto): no BOOT ficam na região de rodata (0x08875600…), longe dos literais do TU; `menu.c` as usa como `extern const` definidas pelo asm de dados (símbolos `type:data` em `symbols/`).
- **Alocação de registradores em funções grandes:** `wsprintf`, `menu_layout`, `menu_item_is_open`, `deck_validate`, `gamestate_fill_partner_list` e `card_id_remap_1a6c` (um `beq` que todas as formas de fonte transformam em `beql`) têm a forma exata (diff estrutural igual) mas registradores/`$fp`/layout de pilha diferentes; ficam em `@asm` com o C sob `NON_MATCHING`. Não vale insistir: o objetivo é o port.
- **Chamadas com menos argumentos que o protótipo** no original (`gim_set_texture(*dl)` em `menu_item_build_text`): declarar a função sem protótipo (`void *gim_set_texture();`) e chamar como o original. Já `mem_swap(heap, a, b)` com 3 argumentos era ilusão do Ghidra: o `li a3, 2` estava içado e reaproveitado na comparação `flip == 2` (`menu_sprite`); passar `2` bate.
- Parâmetros `short` geram `seh` no prólogo (normalização); se o original não tem `seh`, o parâmetro é `int` (`menu_sprite`). `uvoff[0] + (p->x + p->w)` reproduz a ordem dos `addu`.
- Jump tables de funções mantidas em `@asm` ficam no asm de dados; o `@rodata` do `.c` só cobre as tabelas das funções em C (`menu_draw.c`: 0x08875718-0x08875734, sem o padding até 0x08875740).
- **Arrays `const` com inicializador vão para `.rodata`**; se o original tem a tabela em `.data`, declarar sem `const` (`font_color_table`). Ordem das definições = ordem no `.data`.
- Um `.c` com funções em `@asm` que têm literais/templates próprios (`font_init`, `font_glyph_quad`): o `@data` do `.c` só cobre os objetos definidos pelo C (`font.c`: 0x088EE8C4-0x088EE904); os templates ficam no asm de dados com nome e `size:` em `symbols/`. mwcc emite uma seção `.data` por objeto, mas `fix_ld` ainda coloca todas juntas: um `.c` não pode ter dois `@data` separados (pendência: `rename_sections` para `.data.<sym>`).
- `while (lo <= hi) { mid = (lo + hi) / 2; … }` bate a busca binária de `u16_bsearch`; a forma `do/while` com `mid` pré-calculado não.
- `switch` com `case`s compartilhando corpo: um dos casos recebe o corpo no delay slot do `beql`, os demais pulam para um bloco comum (`wc_break_class`: tests na ordem inversa dos `case`, corpos na ordem do fonte).
- O `Makefile` apaga `asm/<m>/` antes do `splat split`: a renumeração dos segmentos (`text_N.s`) deixava arquivos velhos que o `find` continuava montando e linkando (símbolos duplicados).
- Templates de inicializadores locais (`unsigned int cmds[20] = {…}` em `font_dl_glyph_header`) viram um objeto anônimo em `.data` no ponto da função; o `@data` do `.c` tem de cobrir exatamente esses bytes (`font_tags.c`: 0x088EE9E0-0x088EEA30) e os valores têm de ser copiados do ELF palavra a palavra (um erro de byte desloca tudo).
- Divisão com sinal por potência de 2 (`(int)x / 0x800`) gera o ajuste `bgez`/`addiu 0x7FF`/`sra`; ponteiros subtraídos como `(unsigned)a - (unsigned)b` dão `srl`, como `LbnEntry *` dão o ajuste com sinal.
- **`switch` esparso vira cadeia de comparações** (`addiu v0,K; beq a0,v0`), com os testes na ordem inversa dos `case` e **sem ordenação**: em `card_is_in_group_170b` dois ids aparecem fora da ordem crescente porque foram acrescentados no fim da lista original. Testes de pertinência `id == A || id == B || …` nunca batem (a cauda muda); escrever como `switch` com `return 1; default: return 0;` bate sempre (`card_is_in_group_*`, `card_attribute_to_group`, `card_same_name`, `cardinfo_*_cb`). Corpos que terminam em `break` compartilham o `return 0` depois do `switch`; `return 0` dentro de cada `case` gera saltos a mais.
- Comparação com constante dentro de `||`: o primeiro termo pode sair em temporário (`sltiu v0`) e os demais em `$at`; `deck->n_main < 0x28 || deck->n_main > 0x50` bate, e `n_side >= 0x1F` tem de ser escrito `n_side > 0x1E` (regra `$at` acima).
- Variável `unsigned short` lida de memória e usada em `&` com máscara calculada (`card_has_genre_bit`): só com a cópia local `unsigned short w = g[i];` a ordem dos operandos do `and` bate; `(g[i] & mask)` direto inverte os operandos.
- Expressão com chamada embutida (`card_db_ptr->genre + card_index_from_id(id) * 6`) carrega o ponteiro global **depois** da chamada; com o resultado da chamada numa variável o `lui/lw` do global é içado para antes da multiplicação (`card_get_genre`).
- `if (pass == 0) return -1; id = K; do { … } while (id < N); return -1;` reproduz o laço com teste inicial separado (`card_id_from_password`); o `for` equivalente gera o teste no topo.
- Ordem das atribuições iniciais num `case` (`anim1 = 0; anim2 = 0; pack = …; obj[0] = …`) muda a alocação de `$s1..$s3` mesmo com as declarações fixas (`cardinfo_model_cb`: `perm_decls.py` com as instruções como "declarações"). Locais na pilha: o primeiro declarado fica no endereço mais alto (`anim[4]` em 0x60, `params[0x34]` em 0x2C).
- **Dados zerados em `.data`:** `unsigned short x[2] = {0, 0}` vai para `.bss`; o original tem `card_empty_text` em `.data`, o que só sai com `#pragma explicit_zero_data on` em volta da definição.
- `static` em função referenciada por asm (`u16_cmp` passado ao `qsort` dentro de `deck_validate` em `@asm`) tem de cair: o `.s` referencia o símbolo global.
- Ponteiro global definido no `.c` tem de estar na posição certa do `.data` entre os literais das funções vizinhas (`CardDb *card_db_ptr = &card_db;` entre `"recipe_name_x.bin"` e `"cardinfo_"`): literais de string são emitidos na ordem das funções que os usam, e um literal repetido (`"RCP%03d.ydc"`) é emitido uma vez só.
- **Cadeias de `switch` em detalhe** (`card_groups.c`, 41 funções geradas a partir do desassembly): os testes saem na ordem inversa dos `case` e os corpos na ordem do fonte; o **primeiro teste de cada grupo** (último `case` do grupo no fonte) vira `beql` com a primeira instrução do corpo no delay slot, os demais `beq` para o bloco do grupo; se o delay slot do primeiro teste já foi usado pelo prólogo (`sw ra`), o próximo teste do grupo recebe o `beql` (`card_is_group_c`). `case 2: case 4: return 0;` vs dois `case` separados muda o código (merge de ambos). Um `switch` denso (`id - 0x1A90 < 6`) vira tabela de saltos em `.rodata` (`@rodata`). O fim do `@range` deve incluir o `nop` do delay slot do último `jr ra`: cortá-lo duplica a palavra no segmento asm seguinte e desloca todo o resto do módulo em 4 bytes.
- `return !f(x)` gera `sltu v0,zero,v0; xori v0,v0,1`; `f(x) == 0` sai como `xor/sltiu`. `if (hi == 1) return 3; return 2;` dá `bnel`; a forma negada dá `beql`.
- **`__FUNCTION__` vai para `.rodata`** (os nomes `DvdUmdRetryOpenCB` etc. do código de exemplo da Sony em `pmf_umd.c`); por isso essas funções mantêm o nome original, e os `__LINE__` viram literais (401, 459, 525). O fim do `@rodata` exclui o preenchimento de alinhamento do objeto seguinte (o EHP `pack_loading` é alinhado a 16): o segmento `data` gerado cobre os zeros.
- **Ordem das funções no `.c` = ordem das seções no objeto = ordem no binário**, mesmo com `fix_ld` (`.text .text.*` mantém a ordem do objeto): uma função fora de ordem desloca todas as seguintes (`modmgr_none_loading_alias` entre `duel_modules_load` e `duel_modules_unload`).
- Laços de retry (`DvdUmdRetry*`): todos os `return` do original são `break` + um único `return ret` no fim. `ret = f(); if (ret < 0) break;` dá `move s0,v0; bltzl s0 …; move v0,s0`; `if ((ret = f()) < 0) break;` dá `bltz v0 …; move s0,v0` (teste em `v0`, cópia no delay slot); `result = f(); ret = result; if (result < 0) { printf(…, result); break; }` reproduz o `printf` lendo `v0` em vez de `s0`; e `result = g(); if (result < 0) ret = result; else {…}` adia a cópia para o ramo `else` (`DvdUmdRetryReadCB`). Nenhuma dessas formas é intercambiável.
- `if (g >= 0) return 0; x = f(); if (x < 0) return x; g = x; return 0;` (`umd_retry_init`): o `bltzl` para o bloco de criação e o `b` de retorno antecipado só saem com o teste invertido no início.
- **`if ((x = f()) op c)`** (atribuição dentro da condição) testa `v0` e copia para `$sN` no delay slot (`bnez v0,…; move s0,v0`); `x = f(); if (x op c)` copia antes e testa `$sN`. Decide o matching de `movie_decode_*` e dos laços de `DvdUmdRetry*` (que precisam ainda de duas variáveis quando o `printf` lê o valor).
- Mistura de tipos em `a + b` muda a ordem dos `lw`: com `unsigned *mem + int bufsize` o operando convertido é carregado primeiro; `bufsize` `unsigned` em `MovieSnd` bateu `msnd_init`. Alinhamentos em cadeia (`ALIGN64(p + sizeof)`) dobram a constante só se a macro não tiver cast no meio.
- Variáveis mantidas em `$s0..$s8` parecem ser ordenadas por número de usos (`movie_main_loop`: `r` em `$s0` no original, `$s5` na reconstrução); `movie_run`, `movie_main_loop`, `movie_poll_input`, `snd_output`, `*_push_pts`, `vid_init` e `movie_file_init` ficam em `@asm` por isso. Nomes de função duplicados no `symbols/` (`snd_init`, `wave_init`, `movie_play`) quebram o `splat`: prefixar (`msnd_*`).

## Pipeline

```
build/elf/<m>.elf  (PRX relocado, tools/prx2elf.py)
   │  tools/splat_config.py <m>  → config/<m>.yaml   (seções → segmentos; .text e .data divididos nas faixas @range/@data dos .c)
   │  tools/splat_symbols.py <m> → build/<m>.syms.txt (só name/addr/type, formato estrito do splat)
   ▼  splat split                → asm/<m>/*.s, assets/*.bin, build/<m>.ld
   │  sed: remove `.set gp=64` (N64) ; tools/fix_ld.py reordena o bloco DATA e funde .rodata dos .c
   ▼  psp-as (pspdev v20261001) para .s ; tools/mwcc.sh para src/<m>/*.c ; psp-ld -r -b binary para .bin
   ▼  psp-ld -T build/<m>.ld      → build/<m>.rebuilt.elf
   ▼  tools/compare_sections.py build/elf/<m>.elf build/<m>.rebuilt.elf   (compara cada seção pelo vram)
```

Comandos: `make MODULE=BOOT check`, `make check-all` (todos os módulos), `make MODULE=<m> verify` (gate antes do commit: config, split, check, link_map, check-all), `make clean`. Setup das ferramentas externas: `tools/setup_toolchain.sh`. Verificação antes de integrar: `tools/check_file.py MODULE src/MODULE/x.c` (todas as funções do `@range`), `tools/mwcc_check.py SRC.c FUNC MODULE 0xADDR` (uma função, mostra as palavras diferentes), `tools/diff_words.py build/elf/M.elf build/M.rebuilt.elf .text` (depois do link). Desmontar o objeto compilado: `psp-objdump -dr build/x.check.o`.
Correções automáticas no split (`tools/fix_asm.py`): formas VFPU que o psp-as rejeita (`vrot` com lista de rotação, `vpfxd` com máscara) e `.double`/`.dword` (o psp-as alinharia a 8 e deslocaria o `.data`) viram `.word` com os bytes originais; `.align 3` vira `.align 2`.

**Alinhamento das seções:** o link original punha toda seção de entrada em fronteira de 4 bytes, mas os templates de tipos com `__attribute__((aligned(16)))` (Vec4/Mat4 dos handlers EHF, `ehf_cmd.c`: "III" em 0x088ED200 e o Vec4 em 0x088ED210) mantinham os 16. Por isso o segmento não usa `SUBALIGN` (`subalign: null` em `splat_config.py`) e `tools/min_align.py` (chamado pelo Makefile em todo objeto `.s.o`, `.c.o` e `.bin.o`) sobe para 4 o alinhamento das seções menores, o que reproduz o `SUBALIGN(4)` de antes sem truncar os 16.

## Funções que ficam em asm dentro de um arquivo C (`@asm`)

O mwcc emite **uma seção `.text` por função**. `tools/rename_sections.py` (chamado pelo Makefile após cada compilação) renomeia cada uma para `.text.<função>`; assim o linker script pode colocar funções individualmente. Um `.c` declara `// @asm 0xA-0xB` para cada função da sua faixa que continua em asm: `splat_config.py` divide o segmento em `[c, arq] [asm, arq_asm_A] [c, arq] …` e `fix_ld.py` troca cada `arq.c.o(.text)` repetido pela lista `arq.c.o(.text.f1); arq.c.o(.text.f2); …` das funções daquela sub-faixa (pelos endereços em `symbols/`). Os demais objetos C recebem `(.text .text.*)`. A versão C da função fica no arquivo sob `#ifdef NON_MATCHING` para o port. `check_file.py` ignora as faixas `@asm`.

Hoje em asm: `stat_event_record` (0x0883E13C, blocos mortos), `day_threshold` (0x0883EAB4, laço desenrolado pelo compilador; corpo bate, prólogo não), `day_calc` (0x0883ED7C, layout do `case 2`), `gamestate_load` (0x08840A78, só um temporário `$a1`/`$a0` difere).

## Convenção dos arquivos C

```c
// @range 0x088044B8-0x08804508   ← vram coberto pelas funções deste arquivo (em ordem de endereço)
// @asm   0x0883E13C-0x0883E3A4   ← função dentro da faixa que fica em asm (opcional, repetível)
// @data  0x08808830-0x08808840   ← vram do .data que este arquivo gera (literais); opcional, repetível
// @rodata 0x08875598-0x08875600  ← vram das jump tables quando ficam longe dos literais (BOOT); opcional
```
A função também recebe seu nome em `symbols/<m>.txt` (`nome = 0xADDR; // type:func matched src/<m>/arq.c`) para o asm restante referenciá-la.

- **Parâmetro `void *` + cast local muda a alocação de `$s`** (`cip.c`): com `Cip *c` como parâmetro, `c` recebe o `$s` mais alto entre os parâmetros (ordem inversa dos argumentos); com `void *handle` e `Cip *c = (Cip *)handle;` dentro da função, `c` passa a ser alocado junto com os locais (um `$s` abaixo) e `cip_read_card`, `cip_get_image`, `cip_query` e `cip_open_*` batem. Em `cip_query` o teste de nulo é feito no parâmetro (`handle == 0`), não na cópia (`beqz a0` com `move s0,a0` no delay slot).
- **Funções `static` já compiladas têm o conjunto de registradores alterados conhecido pelo chamador**: `cip_draw` mantém `list` em `$a2` através de `jal cip_is_cpm` e `cip_prefetch_cb` mantém `$t0-$t2`/`$a2`/`$a3` através de `jal cip_table`, porque as duas folhas são `static` e definidas antes no mesmo `.c`; sem `static` o chamador salva em `$s`. Só vale para funções definidas antes: `cip_alloc_slot`/`cip_load_next` (antes de `cip_table`) usam a convenção normal. Uma função em `@asm` que chame uma dessas folhas obriga a tirar o `static` (ou perde-se o matching do chamador).
- **Cadeias `a || b || c` em `if (...) return X;`** compartilham um único bloco `move v0,X; b END; nop` colocado após o último teste; os testes intermediários saltam direto para o epílogo com o valor no delay slot (`bnezl v0,END; move v0,zero`). Testes `if` separados geram o padrão "salta por cima do return" (`beqzl cond,CONT; <1ª instrução>; b END; move`). Decide `cip_read_card`/`cip_get_image`/`cip_query` (`c == 0 || !c->ready || c->closed`, `id < first || last < id`, `e == 0 || e->chunk == 0`).
- **`if (a && b) return 0;` gera `bltz`/`bgez` sem likely e com `nop`** (`cip_is_idle`: `if (c->prefetch && c->prefetch_idx >= 0) return 0;`); `if (a) { if (b) return 0; return 1; }` vira `slt`.
- **Bloco compartilhado entre dois caminhos** (`cip_load_cb`): `if (n <= 0) { if (!closed) return 0; } else { ...; if (load_next()) goto done; } busy = 0; done: return 1;` só sai assim com o `goto` (ou equivalente): sem ele o compilador duplica o `busy = 0` ou troca o sentido do `bnezl`.
- **`if (!c->busy) { ... }` antes de um `return` final** gera `bnezl busy,END; move v0,X` (salto direto ao epílogo); `if (c->busy) return X;` gera o padrão "salta por cima". Mesma lógica, código diferente.
- **Ordem de instruções segue a ordem de avaliação do fonte**: `buf = slots + (next * chunks) << 11; next++;` vs `i = next++; buf = ...` (`cip_alloc_slot`); `base = ...; nread = ...;` troca `$t0`/`$t1` (`cip_prefetch_cb`); `(unsigned char *)c + size + 0xAC` vs `(unsigned char *)&c->hdr + size` troca os operandos do `addu` (`cip_header_ready`); `idx = id - c->hdr.first_id;` antes de `cip_table(c)` deixa o `subu` no delay slot do `jal` e carrega `first_id` antes da chamada.

- **`min`/`max`/`ext`/`ins` do Allegrex só saem por intrínseco**: `if (a < b) b = a`, `?:` e variantes com `unsigned short` nunca viram `min`; `__builtin_allegrex_min(a, b)` (macro `ALLEGREX_MIN` em `include/allegrex.h`, com fallback em C para o port) gera a instrução (`fade_apply`). `(x >> 24) & 0xFF` vira `ext` sem intrínseco.
- **Loads de globais não são reaproveitados depois de um join**: em `fade_apply` o `duration` lido para o `min` é reusado no `t = duration - t` (mesmo bloco estendido) mas recarregado para a divisão após o `if`; um local `int dur = fade_state.duration` mantém o valor em registrador e quebra o matching. Usar o global diretamente onde o original recarrega.
- **Ordem dos operandos de `|`, `<`, `addu`** segue o fonte: `rgb | (a << 24)` vs `(a << 24) | rgb` troca os operandos do `or`; `counter > duration` carrega `counter` primeiro, `duration < counter` carrega `duration` primeiro (mesmo `slt`). `if (x1 <= x0) return` vs `if (x0 >= x1)` muda `slt v0`/`slt at` (`fade_wipe_line`).
- **Alocação de `$s` em laços consecutivos** (`fade_apply`): o segundo laço `for` recebe `(j, x)` em vez de reutilizar `(i, y)`: com as mesmas variáveis o par `s0/s1` não troca como no original. **Operando esquerdo de `|`**: `(alpha << 24) | rgb` só bate com `alpha` como variável local atribuída antes (`alpha = (unsigned char)(...)`); inline, o `or` sai com os operandos invertidos.
- **`if (x1 > 480) x1 = 480; x1 -= x0;`** duplica o `subu` no delay slot do `bnezl` e no caminho else; escrever o if/else com duas subtrações não bate.

- **Globais separados vs. struct** (`cardinfo.c`): o estado em `0x08BEA44C` são globais consecutivos, não uma struct: `&struct.membro` sai como `lui/addiu base; addiu +off` (dois `addiu`), enquanto `&global` sai com o endereço direto. Loads/stores de membros não distinguem os dois.
- **`if (A && B) return X; return 0;`** gera: teste A -> salto direto ao epílogo com `move v0,zero` no slot; teste B -> salto para um bloco `move v0,zero` colocado depois do corpo (`cardinfo_get_text`, `cardinfo_has_alt_pict`). O mesmo bloco final serve a `if (p != 0) { ...; if (B) return X; } return 0;`.
- **Locais `unsigned short` são re-estendidos a cada uso** (`andi 0xffff` antes de cada chamada/soma: `pict` em `cardinfo_update`, `ty` em `cardinfo_draw_list_entry`), **parâmetros `unsigned short` não** (o compilador faz um único `andi` e reaproveita). Um `unsigned short x = f()` é truncado no `andi` da atribuição.
- **`h += 2; h += f() >> 6; h += 6;`** mantém as três somas; qualquer forma `h = h + 2 + ... + 6` ou `h += 2; h = h + x + 6;` dobra as constantes em `+8` (`cardinfo_calc_scroll`).
- **Redução de força em laços**: `for (i = 1; i < n; i++) { ry = y + i * 0x16; ... }` gera `addiu ry,y,22` no preheader e `addiu ry,ry,22` no slot do salto de volta; escrever a soma incremental à mão (`ry += 0x16` ou `ry` na cláusula de incremento) muda qual instrução cai no slot (`cardinfo_draw_list_box`).
- **Ordem de declaração dos locais decide a alocação de `$s`** quando os ranges de vida são equivalentes (`int h` antes de `line`/`v` em `calc_scroll`; `int y1, x1` em `draw_frame`); locais declarados num bloco interno não morrem para o alocador (`{ int x5 = x + 5; }` ainda é reaproveitado depois do bloco).
- **Cópias mortas após `b??l`**: o original de `cardinfo_draw` mantém a primeira instrução do bloco destino (já copiada para o delay slot) em 8 blocos else/case, deixando instruções inalcançáveis; o mesmo fonte compilado hoje as remove. Em funções casadas isso só aparece em corpos de `switch` e no join de `if` sem else com `return` (`modmgr_update`, `duel_record_add`). Causa não identificada: `cardinfo_draw` fica em asm.

- **Tamanho de tabelas `.data` vem do layout, não do conteúdo**: `voice_pairs` tem 0x17C bytes (47 registros de 8 + 4 de preenchimento); declarar `[47][4]` encolhe o objeto em 4 bytes e desloca todo o `.data` seguinte (o erro aparece como `.data (length)` e diffs em `.text` muito antes do arquivo). Medir o intervalo até o próximo símbolo.
- **Ordem dos `case` com `default` compartilhado** (`savedata_params_init`): o corpo de `case 1: default:` aparece por último no código; escrevê-lo no meio da lista muda a tabela de saltos.
- **Literais `.data` lidos por asm de outros arquivos** (`"DATA0"`, `snd_bank_cfg`) precisam virar arrays nomeados (ou símbolos em `symbols/`), senão o link falha com `D_xxxxxxxx` indefinido.

- **Laço com contagem constante sem desenrolar** (`snd_bank.c`): `for (i = 0; i < 16; i++)`, `while` e `do { } while (i < 16)` com `i++` no corpo são desenrolados ×8 pelo `-O4,p`; `do { ... } while (++i < 16)` não é, e gera exatamente o laço simples do original (contador incrementado antes do `slti`, ponteiro avançado no delay slot). Útil sempre que o original tem um laço curto de trip count conhecido que não foi desenrolado.
- **`unsigned short` em parâmetro faz o chamador mascarar** (`andi 0xffff` antes do `jal`) além do mascaramento no callee; quando o original não mascara na chamada, o callee foi declarado com `int`/`unsigned int` e trunca internamente (`unsigned short key = id;`).

- **Tabelas que o original percorre a partir do global anterior** (`snd_voice_alloc/free`): o laço começa em `&snd_voice_tab` (a máscara `busy`) e escreve em `4(p)`, `8(p)`, `9(p)`, avançando 12 bytes; um array de registros declarado separadamente gera `0(p)` e o endereço do array. Modelar com um registro cujo primeiro campo é o fim do registro anterior (`SndVoiceRec`) e avançar o ponteiro em 12.
- **Funções que repassam um argumento sem tocá-lo** (`snd_voice_free_one`): o original não carrega `$a1` antes do `j`, porque a função recebe o segundo parâmetro e o repassa. Escrever a chamada com uma constante gera um `move a1,zero` a mais.
- **`r |= 1` vs `r = 1`**: `r = 0; if (bit) r |= 1; else r = 0x20;` gera `ori s0,s0,1`/`li s0,32` como no original (`snd_obj_status`).

- **Globais `volatile`** (`snd_rand`): quando o original recarrega o mesmo global várias vezes na mesma expressão (`lw` repetidos sem store no meio), o estado foi declarado `volatile`. `return g = expr;` devolve o valor calculado sem recarregar o global.
- **Outra toolchain dentro do BOOT**: os wrappers `__sceSas*` em 0x08862D28-0x088634C4 têm prólogo `addiu sp,-16; sw ra,0(sp)`, o código de erro `0x80420100` montado no delay slot e saltos `j` de volta ao epílogo, padrões que o mwccpsp não produz. Ficam em asm. O mesmo vale para o resto até 0x08865260 (canais sceAudio e thread `SceWaveMain`, 41 `j` locais) e para 0x08804000-~0x0881F000 (centenas de `j` locais por bloco de 4 KB); nas faixas já decompiladas o mwccpsp nunca emite `j` dentro da função. Contar `j` com alvo a menos de 0x2000 bytes (`psp-objdump -d … | awk`) separa as duas toolchains antes de gastar tempo numa faixa.

- **Máquinas de estado do save-data (`msd.c`)**: os estados 0..11 e 96..99 de cada `msd_run_*` são um `switch` (cadeia de testes, sem tabela) e o status do utilitário é testado com `if (st == 4 || st == 1 || st == 2) break;` seguido de um `switch (st) { case 0: … case 3: … }`; o código de erro também é `switch` com os `case` explícitos antes de `default` (`case 0x8011032A: case 0x80110325: default:`), mesmo quando caem no mesmo corpo. `err = p->base[7] == 2 ? p->abort_status : p->base[7];` junta os dois caminhos antes da chamada seguinte (o `move a0,zero` fica num único delay slot); `err = …; if (err == 2) err = …;` duplica a preparação da chamada. Para o corpo fora de linha ser o do valor igual (`beqz x → B; A`), escrever `if (x != 0) A else B`.
- **Argumento constante já num registrador**: `li a0,2; beql v1,a0` antes de uma chamada sem preparação visível de argumento indica que a chamada recebe a constante do teste (`sceUtilitySavedataUpdate(2)` depois de `msd_status == 2`); passar a variável (`msd_status`) não bate.
- **Fim do `@data`**: uma global adjacente lida por código ainda em asm não pode ficar dentro do `@data` do arquivo C (o link falha com `undefined reference to D_<addr>`); `msd.c` termina em `0x088F07AC`, antes da palavra usada pela rede.

- **`li` morto entre testes de `switch`** (`msgbox_update_buttons`): `li v0,1` sem uso entre o último `beq` e o `b` do bloco seguinte é a constante de um `case 1:` que divide o corpo com `default:`; o desvio para o corpo (que é a instrução seguinte) some, a carga fica. `switch (res) { case 1: default: r = 5; break; case 2: r = 3; break; case 3: r = 4; break; }` bate; a cadeia `if`/`else if` não.
- **Ponteiros locais para membros de uma global** (`msgbox.c`): `MenuWidget *w = &msgbox.widget; MenuItemDef *d = &msgbox.widget.def;` gera um `lui`/`addiu` próprio para cada um (o original guarda os dois em registradores `s`); escrever `w->def.x` reaproveita `w` com deslocamento. Funções `static` chamadas por uma função que ficou em `@asm` precisam deixar de ser `static` (o objeto asm não vê símbolos locais), o que não mudou o código delas.

- **Laços com limite variável** (`extdata_verify`): `for (i = 0; i < n; i++, p++) sum += *p;` com `i` sem sinal é desenrolado ×8 como os de contagem fixa; o original é `i = 0; if (n != 0) do { i++; sum += *p; p++; } while (i < n);`. Um `unsigned short sum` atualizado em dois passos (`sum += *p; sum = ~sum;`) gera as duas máscaras `andi 0xffff` do original; `sum = ~(sum + *p)` gera uma só.
- **Gerador `rand3` embutido**: o código que embaralha os arquivos YGTF expande o LCG de `rand3_seeds[rand3_slot]` em linha (`*= 0x41C64E6D; += 0x3039; (s >> 16) & 0x7FFF`), com o resultado como `int` (o `%` usa `div`, não `divu`); a primeira chamada mascarada com `& 0x1FF` tem de ser escrita à parte (`(s >> 16) & 0x1FF`, um único `ext`). Trocar índices (`j = RAND3() % len; t = buf[j]; …`) bate; ponteiros (`a = buf + RAND3() % len`) mudam a alocação.
- **`while (a && b)` com chamada no segundo teste**: `while (n < 256) { if (sceIoDread(…) <= 0) break; … }` reproduz o teste no topo mais o teste repetido no fim do original; `while (n < 256 && sceIoDread(…) > 0)` não.

- **Base em registrador para global ou buffer local** (`netsync.c`): `NetXfer *x = &netsync_xfer;` ou `unsigned char *p = pkt;` são dobrados pelo compilador em `lui` + deslocamento por acesso (ou `sp+N`), mesmo com várias escritas; o original guarda `lui`/`addiu` (ou `addiu s0,sp,16`) num registrador e usa deslocamentos. Passar o endereço por um cast de tipo (`(NetXfer *)(char *)&netsync_xfer`, `int pkt[0x40]` com `p = (unsigned char *)pkt`) impede a dobra e bate.
- **Chamada sem argumento a função com parâmetro** (`peer_self_u32`): o original chama `peer_get()` sem passar `i`; reproduz-se com uma definição no estilo K&R (`unsigned char *peer_get(i) int i; { … }`) e protótipo sem parâmetros, o que permite a chamada vazia. Um cast para ponteiro de função gera `jalr`.
- **`check_file.py` mascara os campos relocados** (alvos de `jal`, `%hi`/`%lo`): chamar a função errada com o mesmo protótipo (`memcmp` 0x0881133C em vez de `memcmp2` 0x0880DC98) ou apontar para o campo errado de uma global (`memset(&net.role, …)` em vez de `net + 4`) passa no `check_file` e só aparece no `make check`.

- **`switch` reconhecido pela ordem dos testes** (`net_ctl.c`): cadeias de `x == K` sobre o estado são `switch` quando os testes saem na ordem inversa da dos corpos; `net_update` tem 16 rótulos em 9 corpos, escritos na ordem dos corpos e, dentro de cada grupo, na ordem inversa dos testes. Um `switch` de 0x14..0x1D com `case 0x1A: case 0x1B: break;` gera tabela só quando os `case` estão na ordem dos corpos do original (`case 0x1D` primeiro).
- **`x == 5 || x == 6` vira teste de faixa** (`(x - 5) < 2`); o original testa os dois valores separadamente, o que se reproduz com `if (x != 5 && x != 6) { } else { … }`.
- **Tempo de 64 bits**: `(unsigned long long)(sceKernelGetSystemTimeWide() - t) > 5000000` gera o par `subu`/`sltu` com teste da palavra alta por `bnez` do original; sem o cast o compilador testa a palavra alta com sinal (`bgtz`/`bltz`).
- **`x > 10` e `x >= 11` não são equivalentes para o compilador**: um gera `slti at,…; bnez at`, o outro `slti v0,…; bnezl v0` (`net_update`); quando um não bate, testar o outro.

- **Rótulos vazios que criam a tabela de saltos** (`net_event_guest`/`net_event_host`): um `switch` sobre 0..10 com 6 casos usados vira cadeia de testes; o original tem tabela de 11 entradas, que se obtém acrescentando os valores restantes como `case 2: case 3: case 5: case 9: break;` (ou com `case 0:` quando a entrada 0 também vai para o fim).
- **Atribuição dentro da condição** (`if ((i = net_peer_find(…)) >= 0)`): coloca o `move s0,v0` no delay slot do `bltz v0`; `i = f(); if (i >= 0)` testa `s0` depois do `move` e deixa um `nop`.
- **`x - K <= 3` e `x - K < 4`** (sem sinal) também escolhem registradores diferentes para o resultado do `sltiu` (`at` contra `v1`), como `> 10`/`>= 11`.
- **Vetor endereçado direto no original**: o anel `net_events` (0x08E209F8) logo após `NetSession` é usado como `lui`/`addiu` próprio mais o deslocamento; como membro da struct, o compilador soma o deslocamento do campo ao endereço de `net`. Declarar como global separada.

- **Retorno antecipado com valor** (`net_host`): `if (net_get_state() != 0xB) return 0; … return 1;` gera o `beql v0,K → corpo` com `b` + `move v0,zero` do original; `if (st == 0xB) { …; return 1; } return 0;` põe o corpo em linha. Em funções `void`, o `return;` antecipado não reproduz o mesmo leiaute (`net_toggle_pick` ficou em asm).
- **Laços com ponteiro e índice** (`net_main.c`): a ordem das declarações escolhe os registradores `s` e a ordem no inicializador do `for` escolhe a ordem das instruções (`for (i = 0, p = net_peers; …)` gera `lui s0` / `move s1,zero` / `addiu s0`). Permutar as declarações (`tools/perm_decls.py`) até bater é mais rápido que raciocinar sobre o alocador.
- **Funções-ponte de 8 bytes** (`j alvo; nop`): exports como `net_set_state` e `net_get_param_export` são `return alvo(args);` sem prólogo.

- **`abs` é intrínseco** (`cardlist.c`): o mwccpsp expande `abs(x)` em linha; o original chama a função de 0x0880A5B4, renomeada `int_abs` em `symbols/BOOT.txt` para que a chamada saia como `jal`.
- **Tamanho de struct local decide o quadro** (`card_draw_ehf_frame`): todos os deslocamentos de pilha errados pelo mesmo valor (8) indicam struct local menor que a do original; `EhfFrame` tem 0x68 bytes, não 0x60.
- **Dados de função local**: o modelo de um vetor ou struct local inicializado (`unsigned short label[] = {'A','T','K','/',0}`), um `static` dentro da função e as strings L"…" saem em `.data` no ponto da função, na ordem do fonte; vetores `const unsigned short` globais vão para `.rodata` antes das tabelas de saltos. Um vetor local `= {0}` dentro de um laço gera laço de zeragem byte a byte.
- **Função em asm que tinha dados locais**: ao mover para `@asm`, o modelo do vetor local some do `.o` e o `.data` encolhe. Defini-lo como global nomeada no mesmo ponto do fonte (`cardlist_pair_init`, 0x30 bytes, antes de `cardlist_draw_pair_at`) e em `symbols/`. O `check_file.py` não vê isso; só o `make check`.
- **Faixas de `@asm` pelo próximo símbolo**: o tamanho que o `check_file.py` mostra é o da função compilada, não o do original; o fim da faixa é o endereço da função seguinte em `symbols/BOOT.txt`.
- **Tabelas de `.data` precisam estar em `symbols/`**: o asm referencia o início de cada tabela por `D_<endereço>`; sem a linha `type:data`, o link falha com `undefined reference`.

- **`switch` de duas fases** (`ehf_cam.c`): os comandos EHF testam `phase == 6` antes de `phase == 5` e põem o corpo de 5 primeiro; é `switch (phase) { case 5: …; case 6: …; }` (testes na ordem inversa dos rótulos, corpos na ordem do fonte).
- **Vetor local com inicializador não constante** (`float *out[3] = { &a, &b, &c }`) gera o laço de zeragem byte a byte seguido das stores; `char fmt[] = "fff"` copia o modelo de `.data` byte a byte (ou em laço, a partir de 7 bytes).
- **Posição do parâmetro `float`**: no EABI o `float` vai para `$f12` em qualquer posição, mas a posição na lista muda a ordem das cópias no prólogo (`tgma_apply` tem `t` por último).
- **Ponteiro para subcampo** (`tgma_apply`): `unsigned int *ls = (unsigned int *)(layer + 0x18)` gera o `addiu a0,s2,24` no delay slot do `beqz` do original; acessar `layer + 0x18` e `layer + 0x1C` direto não.

- **Rótulo compartilhado dentro do `switch`** (`snd_group_read_done`): o original testa 0, -1, -2 e põe o corpo de `case 0` antes do código comum; sai com `case -2: case -1: goto shared; case 0: data = …; shared: …`. Sem o `goto`, a ordem dos rótulos que dá os testes certos põe os corpos na ordem errada.
- **Caminho de falha antes do sucesso** (`snd_group_load`): `if (f() == 0) { fail: … } else { …; goto fail; }` reproduz o original que testa o retorno, faz a limpeza em linha e volta a ela com `b` no fim do caminho de sucesso.
- **Corpo inteiro dentro do teste e `return 0` no fim** (`snd_fader_update`): `if (a != b || n != 0) { …; return 1; } return 0;` gera o `beqzl … move v0,zero` direto para o epílogo; com `if (a == b && n == 0) return 0;` no começo sai `bnez` + `b`.
- **`sqrtf` também é intrínseco** (vira `sqrt.s`): o BOOT chama a rotina VFPU em 0x0881D1A4, renomeada `sqrtf_vfpu`, como `abs` → `int_abs`.
- **Laço que o compilador desenrola**: `for (i = 5; i >= 0; i--)` com 6 iterações sai desenrolado; o original mantém o laço, o que se obtém com `do { i--; …; } while (i >= 0);`.
- **`abs` à mão**: `if (d < 0) d = -d; v += d;` gera `bgezl … addu` / `negu; addu`; o intrínseco `abs` gera `neg` em vez de `negu`.
- **Campos acessados por ponteiro-base** (`snd_obj_3d`, `snd_slots_update`): quando o original carrega vários campos ou globais pelo mesmo registrador (`addiu a1,s5,52` e depois `0(a1)`, `16(a1)`, `24(a1)`), há uma sub-struct (`SndPos`) ou um bloco de globais (`snd_3d`, `snd_cur_slot`+`snd_slot_tab`) acessado por ponteiro.
- **Matrizes locais em ordem inversa**: o mwccpsp põe a primeira declarada no endereço mais alto da pilha; `snd_obj_3d` declara `in, d, v, dir, n` para que fiquem em 112, 96, 80, 64, 48.
- **Rotinas soft-float do GCC** (`fp-bit.c`) no BOOT: `__adddf3` 0x088180B8, `__subdf3` 0x08818120, `__muldf3` 0x08818194, `__divdf3` 0x0881850C, `__fixdfsi` 0x08818CA0, `__extendsfdf2` 0x088179A8, `__truncdfsf2` 0x08818DEC, `__muldi3` 0x08816C3C; são os nomes que o mwccpsp emite para `double` e `long long`.

- **Laço que continua depois de achar** (`bgm_slot_play`): o original guarda o último slot vazio e só para num slot suspenso; o `b` de volta ao incremento (em vez do fim do laço) mostra quando o `break` não existe.
- **Parâmetro `unsigned short` vs conversão no chamador**: um parâmetro `unsigned short` é renormalizado (`andi …,0xffff`) a cada uso e a cada repasse a um parâmetro `int`; se o original passa o registrador cru, o parâmetro é `int` e as conversões `(unsigned short)` estão nas expressões (`snd_obj_start_retry`, `voice_start`).
- **Sub-struct pelo registrador-base** (`SndStream` em `SndObj +0xA8`): `s = &o->s` antes de uma sequência de stores gera o `addiu s0,s2,168` do original e os deslocamentos relativos a ele.
- **`default: return;` no fim do `switch`**: o `b` para o epílogo com `nop` do original; com `break` o compilador põe o primeiro `lw` do epílogo no delay slot.
- **Laços sobre listas intrusivas** (`snd_group_stop`, `snd_duck_update`): `for (;;) { if (o == 0) break; cur = o; o = snd_list_next(l, o); … cur … }` reproduz o teste no topo e o `move` no delay slot da chamada seguinte.
- **`tools/splat_config.py`**: uma faixa `@asm` que termina junto com o `@range` não gera mais um segmento `c` vazio (que fazia o linker descartar as seções do arquivo seguinte).

- **Retorno 0 por dois caminhos** (`snd_obj_pause_update`): com `f = &o->fade[2];` antes de `if (o->fade[2].cur == o->fade[2].target) { if (f->count == 0) { …; return 1; } } return 0;` o primeiro teste vira `bne` para o `move v0,zero` final com o `addiu` de `f` no delay slot e o segundo vira `bnezl` direto para o epílogo, como no original.

- **Temporários por laço** (`snd_echo_add`): dois laços iguais em que o contador de um e o temporário do outro trocam de registrador indicam um `int v` declarado dentro de cada corpo; com um `v` único os dois laços usam os mesmos registradores.
- **Índice em vez de ponteiro** (`snd_streams_sorted`): `out[i]`/`out[j]` deixam o compilador reduzir o endereço a um ponteiro que avança 8 bytes, calculado só depois do teste de entrada do laço interno; com ponteiros explícitos o cálculo sai antes do teste.
- **Valor de retorno guardado numa variável** (`snd_voices_update`): `end = f(); if (end & bit)` gera `and v1,v0,s1`; `if (f() & bit)` gera os operandos na outra ordem.
- **Divisão por 2 do original**: `x >> 1` seguido de `if (x < 0) x++` (não é `x / 2`, que soma o sinal antes do deslocamento); aparece no eco do mixer.

- **Ponteiro local recalculado a cada iteração** (`snd_thread_main`): `SndFader *m = &snd_master;` declarado dentro do corpo do `for (;;)` gera o `lui`/`addiu` no começo de cada volta, como no original; os testes em `snd_master.cur`/`.target` continuam por endereço direto e só a chamada e a leitura final passam por `m`.
- **Nomes de globais únicos no BOOT**: o splat rejeita símbolo duplicado (`Duplicate symbol detected`); antes de nomear uma global, `grep` em `symbols/BOOT.txt` (o `movie.c` já tinha `snd_out_idx`).

- **Dois retornos de erro seguidos** (`snd_obj_begin`): `if (grp == 0 || d == 0) return -1;` gera `beqzl grp → epílogo` com o `-1` no delay slot, seguido de `bnezl d → corpo`; dois `if` separados geram `bnez` + `b` para cada um.
- **Ordem dos testes de um `switch` com `case`s agrupados**: os testes saem na ordem inversa dos rótulos também dentro do grupo; testes `4, 3, 1, 2` vêm de `case 2: case 1: …; case 3: case 4: …`.
- **`|=` condicional por valor** (`snd_obj_begin`, envelope SAS): `switch (m) { case 1: a |= 0x4000; break; … }` gera a cadeia `beql m,K → chamada` com o `ori` no delay slot; a cadeia `if/else if` gera `bnel` + `b`.
- **`if (x < 0) x = 0;` seguido do teste de teto**: escrever `if (x >= 0x54) x = 0x53;` (e `if (x >= 0x80) store 0x7F; else store x;`) dá o `slti v0` sem likely e o `sb` duplicado do original; `x > 0x53` põe o resultado em `$at` com `bnezl`.

- **Global inicializada e depois percorrida** (`snd_thread_init`, `snd_cur_slot`): `c = &snd_cur_slot; c->slot = -1; do { c->obj[i] = 0; } while (++i < 4);` gera os dois `lui` antes do `sh`, como no original; escrever direto em `snd_cur_slot.slot` agenda o `sh` logo após o primeiro `lui`.

- **Registradores temporários vivos através de uma chamada** (`snd_streams_decode`): o original mantém `$t7`, `$t8` e `$v0` (ponteiros e contador da mistura) através das chamadas a `snd_stereo_widen`/`snd_box_filter`, funções do mesmo arquivo que não tocam nesses registradores. O mwcc build 219 com `-O4,p` não faz isso: testes com folha definida antes no mesmo arquivo, com e sem pressão de registradores, sempre salvam os valores em `$s`/pilha. Uma função com esse traço não bate; fica em `@asm` com o C sob `NON_MATCHING`.

- **Ponteiro que pode ser arquivo ou instância** (`ehf.c`): `i = *(int *)e == EHF_MAGIC ? ehf_resolve(e) : e;` (macro `EHF_INST`) gera o `bnel` com `move v0,a0` no delay slot do original; `if (magic) e = ehf_resolve(e);` gera `bne` + `nop` ou um `bnel` que duplica a carga seguinte.
- **Retorno escondido**: uma função que termina com `li v0,1; sb v0,…` e retorna sem tocar mais em `$v0` é `int` com `x = 1; return 1;` (`ehf_inst_reset`); declarada `void`, o compilador evita `$v0` como temporário em toda a função e os registradores mudam.
- **Ordem dos parâmetros com float e ponteiro**: `dl_tex_scale(list, 1.0f, 1.0f)` e `mat4_translate2(m, x, y)`, não `(x, y, m)`. Os registradores são os mesmos (`$a0`, `$f12`, `$f13`), mas a ordem de avaliação dos argumentos muda o que vai para o delay slot do `jal`.
- **Parâmetros u16 passados já estendidos**: se o chamador carrega com `lhu` e o chamado usa o valor sem `andi 0xffff`, o parâmetro é `int` (`ehf_track_eval(…, int start, int frame)`); declarado `unsigned short`, o chamado mascara de novo e o chamador avalia os argumentos em outra ordem.
- **Cópia de struct vs. elemento a elemento**: `*cx = global;` copia por `lwc1`/`swc1` (às vezes com um `lui` por palavra); `d.x = g.x; …` com `int` sai em `lw`/`sw`, um `lui` por elemento (`ehf_draw` usa a segunda forma, `ehf_track_eval` a primeira).
- **Teste de laço no topo** (`ehf_clip_step`): `for (;;) { if (cmd >= end) break; … }` mantém a comparação no começo do laço, como no original; `for`/`while` são rotacionados com o teste no fim. Para um laço que sai com `return` (`ehf_list_remove`), `do { if (achou) goto found; k = k->next; } while (k != head); return head; found: …` põe o corpo do achado depois do laço.
- **Combinação de transformações de cor** (`ehf_draw_list`): calcular os oito valores em temporários e só então gravar no struct reproduz as gravações agrupadas no fim; `cx.add[i] += …` grava campo a campo.
- **Matriz local de 18 floats** (`ehf_draw_begin`): um buraco de 8 bytes acima de um `float[16]` no quadro do original indica uma matriz declarada maior (ou um local não usado); `float m[18]` reproduz o leiaute.
- **Valores em registradores temporários através de chamada a função do mesmo arquivo** (`ehf_draw_text`): o original deixa o ponteiro do caractere em `$v0` durante `ehf_track_eval`, que não usa `$v0`. Isso só se reproduz se o chamado compilar exatamente igual; com o chamado em `@asm`, o chamador também fica em asm.

- **Teste do valor retornado** (`ehp_find`, `ehp_read_entry`): `if ((e = f()) != 0)` testa `$v0` com a cópia para `$s` no delay slot, como no original; `e = f(); if (e != 0)` testa o registrador `$s`.
- **Byte alto como versão** (`ehp.c`): `p->magic >> 24 & 0xFF` com `magic` `int` gera `lw` + `ext`; com `unsigned` sai `srl`, e um bitfield de 8 bits sai `lbu`.
- **Global repartida**: quando o original endereça uma tabela por um símbolo próprio (`addiu …,%lo(tab)` com o campo em +4), a contagem e a tabela são duas globais (`ehp_mount_n` 0x08903860, `ehp_mount_tab` 0x08903864), não um struct; com struct, a contagem é relida depois de cada gravação na tabela.
- **Mesmo campo no teste e no corpo do laço** (`ehp_unload`): `while (e->name != 0) { f((char *)p + *(int *)e); … }` relê o campo no corpo, como o original; com `e->name` nos dois lugares o compilador reaproveita a carga do teste.
- **Inicialização dentro do `for`** (`ehp_read_entry`): `for (i = 0, m = tab; …)` põe o `addiu` do ponteiro no delay slot do teste de entrada, depois do `i = 0`.

- **Soma de inteiros mantém a ordem; ponteiro não** (`gfx_copy_frame`): `(void *)(tab[b] + (int)edram)` gera `addu v0,v1,v0` como no original; com aritmética de ponteiro (`(char *)edram + tab[b]`), o compilador normaliza os operandos.
- **Resultado de chamada usado como argumento e guardado** (`gfx_draw_target`): `dl_set_cur_list_base(layer = dl_select_layer(layer, &size));` passa `$v0` direto e copia para `$s` em paralelo; com duas instruções, o argumento sai do registrador `$s`.
- **Estado repartido em dois structs** (`gfx_state` 0x08905084 e `gfx_flip` 0x0890508C): o original endereça `on_flip` como `8($s0)` com `$s0 = &hcount`, então o bloco a partir de `hcount` é um objeto próprio.
- **`ins` para endereço não-cacheado** (`dl_state_reset`): `ALLEGREX_INS((unsigned)tab, 4, 28, 4)` (ver os intrínsecos Allegrex no começo deste arquivo; máscara + or em C nunca gera `ins`). Antes de dar uma função como perdida por `min`/`max`/`ins`/`ext`, usar `include/allegrex.h`.
- **Dados de funções em asm**: strings e tabelas usadas só por funções que ficaram em `@asm` precisam virar globais nomeadas no C (`gfx_host_dir`, `gfx_tga_header`…), senão o `.data` do objeto encolhe.

- **Laço de zeragem byte a byte** (`mat4_inv_rigid`, `ehsys_0883C50C`): `beqz p; li n,16; sb zero; addiu n,-1; bnez` no começo de um bloco é o `= { 0 }` de um local (array ou struct). `EhfVec4 r = { 0 }; r.x = …; out[0] = r;` reproduz até a cópia do struct pelo stack.
- **Template de local inicializado vai para o começo do `.data` do objeto**: o mwcc põe o template anônimo (`@282`) numa seção própria que o linker coloca antes das globais do arquivo. Quando o original o tem no meio dos dados, copiar de uma global nomeada (`EhfVec4 r = ehf_row3;`) gera o mesmo código (só as palavras não sobrescritas são lidas) e mantém a ordem.

- **Endereço de campo guardado entre chamadas** (`gim_upload`, `gim_find_block`): quando o original faz `addiu $sN, root, 4` no delay slot da primeira chamada e depois `lw 0($sN)`, o fonte tinha um ponteiro para o campo: `unsigned int *sz = &root->size;` usado nas duas buscas `(char *)root + *sz`.
- **Parâmetro modificado num laço** (`gim_walk`, `gim_block_find`): quando os `$s` dos parâmetros saem em ordem inversa à do original, copiar o parâmetro que o laço avança para um local (`GimBlock *b = start;`) reproduz a alocação.
- **Ordem dos `case` com corpos distintos** (`gim_upload`): os corpos saem na ordem do fonte, então `case 4: case 8: size /= 2; break;` vem antes de `case 0: … size *= 2;` quando o original tem a divisão primeiro, mesmo com a tabela de saltos.

- **Bitfields** (`heap.c`): o mwcc aloca do bit menos significativo; um campo de 1 bit no topo da palavra é lido como `lbu +3; sll 24; srl 31` e gravado com `lbu/andi 0x7f/ori 0x80/sb`. Um campo de 6 bits comparado direto (`h->pad < 0x11`) ganha um `andi 0xff` a mais; lido para um `int` local antes da comparação sai como no original (`slti`).
- **Comparação com `sizeof`** (`heap_alloc`): `tabsize < (n + 2) * sizeof(HeapEnt)` gera `sltu` (o `sizeof` torna a expressão sem sinal); com `* 4` sai `slt`.
- **Dois nomes para o mesmo valor** (`heap_create`): `subu v0,a0,a0` não dobrado no original vem de duas variáveis que o alocador juntou no mesmo registrador (`h = mem = malloc(...)`; `pad = (char *)h - (char *)mem`); com uma só variável o compilador dobra para zero.
- **Retorno compartilhado no fim** (`heap_merge`): ramos que terminam todos em `return 1` saem com o bloco comum no fim da função quando o fonte usa `if/else if` com um único `return` depois; `return` dentro de cada ramo põe o bloco no meio.

- **Condição negada guardada numa variável** (`pad_angle`): `moved = !(abs(dx) < 0x20 && abs(dy) < 0x20); if (moved) …` gera `slti; beqzl …; xori` como no original; o `if (!(…))` direto vira `beqz` + `bnezl`.

- **Palavras de comando do GE** (`dl.c`): o `or` com o parâmetro mais à esquerda sai por último no original, então `func | (mask << 16 | 0xDB000000 | ref << 8)` (e `psm | (shift << 2 | (start << 16 | 0xC5000000 | mask << 8))`); sem os parênteses o mwcc começa pelo primeiro operando. `ext` sai de deslocamento + máscara: `(p >> 24 & 0xF) << 16` (BASE), `x >> 8 & 0xFFFFFF` (float para o GE); `((p & 0xFFFFFFF) >> 24)` também gera `ext` numa variável, mas não num parâmetro convertido.
- **Índice crescente em array local** (`dl_draw_array`, `dl_prim_begin`): `n = 0; cmd[n++] = …` (cada acesso recalcula `sll/addu` sobre `$sp`); `cmd[n] … n += 2` gera endereço base fixo.
- **Cadeia de testes em ordem inversa = `switch`** (`dl_material`, `dl_light_color`, `dl_light_spot`): `li 4; beq; li 2; beql; li 1; beql` vem de `switch` com `case 1, 2, 4` nessa ordem no fonte; os testes em ordem direta (`beqz; li 1; bnel; li 2; bnel`) são `if/else if` (`draw_sprite`).
- **Valor usado só como temporário vai para outra posição do array** (`dl_disable`, `dl_scissor`): quando um `int` local cai no registrador errado, declará-lo `unsigned int` (ou usar um slot do próprio array, `cmd[3] = x + w - 1; … | cmd[3]`) muda a ordem de alocação.
- **Locais `float` inicializados antes do array** (`dl_viewport`): o original converte os parâmetros e grava nos slots antes do laço de zeragem; isso só sai com `float x = cx; …` declarados antes de `unsigned int cmd[4] = { 0 };` (inicialização na declaração, na ordem do stack).
- **`push` em laço que devolve o ponteiro** (`dl_draw_array_n`): o original mantém a lista em `$v0` com `bnezl … move a0,v0`; reatribuir a variável do parâmetro (`list = dl_push1(list, …)`) leva para `$a0` e acrescenta `move v0,a0`; uma variável nova (`p = dl_push(…); p = dl_push1(p, …); return p;`) reproduz.

- **Argumento `float` por último no protótipo** (`spline_eval`): quando o `mtc1`/`mov.s` do `$f12` cai no delay slot do `jal`, o float é o último argumento do fonte (`vec3_scale_w(out, a, s)`); com o float primeiro ele é avaliado antes dos ponteiros.
- **Variável nova para o valor derivado de um parâmetro** (`spline_eval`): `f = t - k` mantém `t` em `$f12` sem cópia; `t -= k` obriga a copiar o parâmetro para um `$f` salvo na entrada. Já o reuso de um parâmetro morto (`ring = (start + k) % ring` em `spline_eval_ring`) economiza um `$s` como no original.
- **Argumentos avaliados da direita para a esquerda só via temporário** (`spline_eval_ring`): quando o original calcula o terceiro argumento antes do segundo, guardar o terceiro numa variável antes da chamada.

- **VFPU no mwcc** (`mtx.c`, 30/30 matching): o assembler embutido do mwccpsp aceita VFPU. Funções C com blocos `asm { … }` no meio (o original guarda a matriz corrente em M300 entre chamadas) e funções inteiras `asm void f(…) { …; jr ra; <delay> }` reproduzem o original. Sintaxe que bate: `sv.q C300, 0(p)` com `register float *p` local (o C carrega o ponteiro, o bloco usa o registrador), `;` separando instruções num macro de uma linha, `vrot.q C010, S100, [0, c, s, 0]` (imm decodificado do word: bits 0-1 posição do cos, 2-3 do sin, 4 nega o sin), `vcst.s S101, VFPU_2_PI`, `vfim.s S123, -1.0` (literal float), `vpfxs -X, X, X, X`, `vcmp.s ez, …`, `vcmovt.s S200, S203, 0`; o que não tiver sintaxe conhecida vai como `.word 0x…` (`vpfxd` em `mtx_look_at`). Para o port, cada bloco tem um `#else` em C sobre `vfpu_m300`.

- **Handlers EHF** (`ehf_cmd.c`, `ehf_cmd2.c`): o ponteiro para os argumentos é um local inicializado na declaração (`float *a = cmd->a.f;`), calculado no delay slot do primeiro teste; quando o original o calcula depois de uma chamada no `$s` (`ehf_cmd_trs`), a atribuição vem antes da chamada (`a = …; mtx_push();`). Fases múltiplas são `switch (phase)` com os `case` na ordem dos corpos. Um teste que só pula o corpo é `if (cond) { … } return 0;`, não `if (!cond) return 0;` (`ehf_cmd_hold`, `ehf_cmd_loop`). O array de saídas de `ehf_cmd_args` é inicializado na declaração (`void *out[2] = { &pos, &dir };` → laço de zeragem + atribuições) e declarado antes do `char fmt[] = "…"` (template copiado byte a byte depois). Um vetor `{ a[0], a[1], a[2], 1.0f }` gera template {0,0,0,1} copiado inteiro e sobrescrito (`ehf_cmd_cull`); `node->time` relido em cada uso, sem local (`ehf_cmd_spin`).
- **Templates de função em asm:** as seções `.data` do objeto (templates anônimos e globais nomeadas) saem na ordem em que aparecem no fonte; quando a função dona de um template fica em `@asm`, o template vira global nomeada definida no ponto do arquivo que mantém a ordem (`ehf_ribbon_p0` depois de `ehf_cmd_prim_args` em `ehf_prim.c`), e as funções em C que copiavam um template dela copiam byte a byte de `unsigned char fmt_x[4]` com o endereço do array local guardado antes (`f = (char *)fmt; fmt[0] = ehf_fmt_ii[0]; …`), o que reproduz a cópia do template (`ehf_cmd2.c`).
- **Ordem das declarações e endereço na pilha:** nos handlers EHF o primeiro local declarado fica no endereço mais alto (`Vec4 pos; Vec4 dir;` → pos acima); quando não bater, permutar só os locais da pilha.

- **Função `static` chamada pelo vizinho** (`ehf_vtype_info`, `ehf_vertex_set`): o original guarda argumentos em `$t` através da chamada só quando a função chamada é `static` no mesmo arquivo (o mwcc conhece os registradores que ela usa). Uma `static` chamada por função mantida em asm recebe `type:func static` em `symbols/` e `fix_ld.py` gera `PROVIDE(nome = endereço)` para o asm.
- **`switch` sem `default` e retorno no fim** (`ehf_vertex_set`): os `case` internos que não casam caem num `return 0` comum no fim; um `default: return 0;` explícito muda o layout. `default:` como primeiro rótulo põe o retorno padrão logo depois dos testes (`ehf_cmd_callback`, `ehf_cmd_jitter`).

- **Literal composto copia pela pilha** (`ehf_cmd_ptcl_tetra`, `ehf_ptcl_vel_radial`): `t->dir[0] = (Vec3){ 1.0f, 1.0f, -1.0f };` gera o padrão do original (cada float do template lido com `lwc1`, gravado num temporário da pilha e copiado ao destino), com os templates na ordem do fonte; um local `Vec3 d = {…}` em bloco próprio põe os temporários em outros endereços. Um vetor constante lido com `lwc1` mas guardado fora da ordem dos templates do arquivo é global nomeada copiada por valor (`Vec4 x = ehf_ptcl_x;`, definida no topo de `particle.c`).
- **Ordem dos parâmetros do protótipo decide o delay slot** (`ehf_cmd_ptcl_drag`): o mesmo `vscl` exportado matcha declarado `vec3_scale(out, a, s)` num arquivo e `(s, out, a)` em outro; quando o `mov.s $f12` cai no delay slot, declarar o float por último.
- **Canais de cor interpolados** (`ehf_cmd_ptcl_color_keys`): `ca = a >> 24 & 0xFF; cb = …; color |= ((unsigned int)(ca * t + cb * u) & 0xFF) << 24;` com `ca`/`cb` `float` reproduz a conversão de cada canal no registrador do original; a expressão inteira numa linha (macro) funde a multiplicação e troca os `$f`. `(unsigned int)cmd->argc >> 1` dá `srl` (com `int` sai `sra`); `if ((argc & 1) || argc < 2) return 0;` dá o par `bnezl`/`beqzl`.
- **Cadeia de atribuição** (`ehf_cmd_sprite`): `base = v = alloc(…)` copia primeiro para `v`; `v = base = …` inverte os `move`.
- **Parâmetro copiado para `$s` cedo** (`ehf_ptcl_cone`, em asm): quando o original guarda o ponteiro de saída num `$s` só depois das primeiras contas, mas o nosso o copia na entrada (e os temporários mudam de `$t` para `$a`), nenhuma variação de declaração mudou isso; idem para o nome carregado em `$v1` antes do `ehp_find` em `ehf_cmd_tex`.

- **Permutar a ordem dos comandos, não só das declarações** (`efs_load`): `tools/perm_decls.py` aceita comandos inteiros no lugar de `{DECLS}`; a ordem das atribuições independentes (`end = …; base = …; str = …;`) decide os registradores temporários e a ordem dos `lw` quando a das declarações não basta.
- **Busca com saída por `goto`** (`efs_start`): `for (…) { if (livre) goto found; } return 0; found:` reproduz o laço que cai direto no `return 0`; `break` + `if (i >= N) return 0;` gera um teste a mais.
- **Ponteiro local para a global grande** (`efs.c`): `EfsMgr *e = &efs;` faz o primeiro acesso sair absoluto (`lui 0x890; lw 12744`) e os seguintes pela base `$s0` com `lui 0x1; addu` (deslocamentos > 0x7FFF); funções que usam só endereços absolutos escrevem `efs.campo`. Dá para misturar os dois na mesma função (`efs_update`, `efs_inst_free`).
- **Ponteiro para o elemento antes do teste** (`efs_term`, `efs_load`): `EfsInst *inst = &efs.insts[i]; if (inst->mem) efs_inst_free(inst);` põe o cálculo do argumento no delay slot do `beqz` e deixa o `jal` com `nop`; indexar duas vezes gera `beqzl`.
- **Blocos esvaziados pelo branch-likely ficam no binário quando o bloco tinha outro predecessor** (`efs_set_args`, `efs_inst_init`): quando o original repete uma instrução logo depois de um `b`, o fonte tem o código duplicado nos caminhos (um `dst++` em cada `case`, `argq = 0` no `else` comum às duas condições). `efs_run` tem esses blocos em todas as fases e ficou em asm.
- **Retorno do valor de entrada sem tail call** (`light_reset`): `if (list == 0) return list; list = light_apply(list); return list;` dá `move v0,s0` e `jal` + epílogo; `return light_apply(list)` vira `j`.
- **Parâmetro recebido como handle** (`efs_send`): `void *h` copiado para `EfsInst *inst = h` muda a ordem de alocação dos `$s` entre os parâmetros.
- **Dados de um arquivo terminando fora do alinhamento de 16** (`camera.c`): quando o próximo objeto do original era alinhado a 16 mas o trecho seguinte fica em asm, o `@data` termina no fim real do último objeto (0x088ED7AC) e o preenchimento vai para o asm.

- **Protótipo local escolhe a ordem dos argumentos float** (`tms_draw`): a mesma `dl_tex_offset` definida como `(float u, float v, list)` em `dl.c` é declarada em `tms.c` como `(list, u, v)`; os registradores são os mesmos (`$a0`, `$f12`, `$f13`), mas a ordem da avaliação muda o que vai para o delay slot do `jal`.
- **`switch` sobre um bit** (`tms_draw`): dois testes `beql v,1` / `beqzl v` seguidos de corpos na ordem 0, 1 são `switch (flags & 1) { case 0: …; case 1: …; }`, com `continue` dentro dos `case`.

- **`check_file.py` não confere o destino dos `jal`** (`model_draw`): a relocação `R_MIPS_26` é comparada só pelo opcode, então chamar `mtx_mark_cur_dirty` no lugar do invólucro `model_mtx_dirty` passa no arquivo e só falha no `make MODULE=BOOT check`. Funções minúsculas entre duas funções nomeadas (um `j` + `nop`) costumam ser esses invólucros.
- **Laço de contagem com teste no topo** (`model_load`): `while (1) { if (*p == -1) break; p++; i++; }` mantém o teste antes do corpo (`beql` para a saída com a gravação no delay slot); `for (…; *p != -1; …)` é rotacionado pelo compilador.
- **Matriz identidade carregada float a float** (`model_load`): o template de 64 bytes copiado com 16 `lwc1`/`swc1` vem de uma struct de 16 `float` com `aligned(16)`; um `Mat4` com `float m[16]` gera o laço de cópia de pares de palavras.

- **`else` com a constante que o compilador já sabia** (`anim_eval`): um `beql v,ffff` com `andi v1,a3,0xffff` (a constante) no delay slot vem de `if (b != 0xFFFF) { … } else { b = 0xFFFF; }` — atribuição redundante no fonte que o mwcc materializa a partir do registrador da constante.
- **Ordem da declaração muda o modo de cópia do template** (`anim_eval`): `MatF id = {…}` declarado antes de `unsigned short b = t->root;` sai como laço de cópia de palavras; declarado depois, sai float a float (`lwc1`/`swc1`) como no original.
- **Peso extra em `$f14`** (`model_update`): um produto calculado num registrador alto (`$f14`) antes de uma chamada é o terceiro argumento float da chamada (`anim_blend(…, m->frame * k)`), não uma variável local.

- **libduel_eng** (`include/duel.h`): o estado do duelo é um bloco de 0x3840 bytes em `0x08915E5C` (`Duel`: dois `DuelPlayer` de 0xFAC, modo, lista de efeitos de 8 bytes em +0x276C). Os acessos casam com `DuelPlayer *pl = &duel.players[p & 1]; … pl->field[i]` (índice, não ponteiro incrementado); o compilador indexa por `mult` com 0xFAC. Contadores de laço declarados antes do acumulador (`int i; int n = 0;`).
- **`i <= 10` gera `slti at,i,11`** (`field_count.c`): laços até 11 com `slti at` no original foram escritos com `<=`; `i < 11` gera `slti v0`.
- **MIN/MAX em ternário** (`duel_count_free_monster_zones`): `n = MIN(n, 5 - f(p)); n = MAX(n, 0);` reproduz a segunda chamada de `f` e o `blezl`; o mesmo com `if` não casa.
- **Campos de 16 bits lidos por máscara, não por bitfield** (`DuelEffect.src`, `marks`): o original carrega com `lhu` e separa com `andi`/`ext`; macros `x & 0xFF` / `x >> 8 & 0xFF` reproduzem, structs de bytes ou bitfields geram `lbu` ou cópia pela pilha.
- **`switch` com casos em ordem crescente e corpos na ordem do fonte** (`tribute.c`): os testes saem na ordem inversa dos rótulos e os corpos na ordem em que aparecem; um grupo de ids que só retorna 0 é um único bloco de `case` (dois blocos `return 0` separados geram um `beql` direto ao epílogo para um deles). Cadeias de `if (c != A && c != B …) return 0;` viraram `switch` dentro de um `if (… && …)` (`duel_double_tribute`).
- **Ordem dos operandos de `&` decide registradores** (`SLOT_ACTIVE`): `faceup & ~(flags >> 5 & 1) & ~(flags >> 1 & 1)` carrega `faceup` em `v1`; com o termo de `flags` primeiro os registradores trocam.
- **Comparação com valor montado de 16 bits** (`duel_count_tributable_except`): `except != (unsigned short)(q & 0xFF | (z & 0xFF) << 8)` gera o `andi 0xffff`; o laço de `z` é `int` (com `unsigned` sai `sltiu`).
- **`if (f()) z = g(); else z = -1; return z;`** gera `beqzl v0 → li v0,-1` com a chamada no caminho direto; o ternário ou `if (!f()) return -1;` gera `bgtzl`/`bnezl` com a chamada depois.
- **`if (x) return 0;` seguido de mais código gera `beqz x; nop; b fim; move v0,zero`** (`field_st.c`): o `return 0` vira bloco próprio com desvio ao epílogo; quando o original testa duas condições assim em sequência, são dois `if` separados, não um `||`. Um `&&` de três termos dentro de um único `if (…) return 0; return 1;` reproduz o `beqzl → li v0,1` (`duel_can_place_st`).
- **Limite do laço por ternário** (`duel_count_field_cards`): `end = fzone != 0 ? 11 : 10;` com acesso direto `duel.players[p & 1].field[i]` (base calculada depois do teste do laço); `if/else` inverte os blocos e um `DuelPlayer *pl` local adianta o cálculo da base.
- **`bgtzl → li v0,1` seguido de outro teste** (`duel_monster_can_act`): é um único `if ((int)(x & 2) > 0 || (a == 0 && b == 0)) return 1;`; com dois `if` o compilador inverte para `blezl`. Num `switch` cujos casos terminam em `break` antes de `return 1`, um `default: return 1;` explícito cria um segundo bloco `li v0,1` que o original não tem.
- **Bitfields de `DuelCard` lidos por endereço fixo** (`duel_field_protected`): `duel.players[p & 1].field[z].card.uid_hi` direto (sem `DuelSlot *` local) faz o compilador guardar os endereços +0x31/+0x32 em `$s` antes do laço, como no original; com o ponteiro local a base sai calculada antes do teste de `id`.
- **`case` que cai no grupo seguinte** (`duel_attack_forbidden`): quando o `return 0` de um caso condicional é o mesmo bloco do grupo de ids que sempre retorna 0, o fonte é `case A: if (!cond) break; case B: case C: return 0;` (queda), não um `return 0` próprio. Um teste `if (id == X) … else if (id == Y) … else return 0;` cujos corpos saem na ordem inversa dos testes é um `switch` com `default: return 0;` (`duel_can_attack`).
- **Uma única leitura de `flags` reaproveitada** (`duel_attack_forbidden`): `unsigned int f = slot.flags;` para os testes de bit e depois `SLOT_ACTIVE(&slot)` (a macro, não a expressão com `f`): o compilador reaproveita o registro de `f` e a ordem `faceup` primeiro se mantém.
- **Campos de struct preenchida por chamada copiados para locais** (`duel_attack_check`): quando o original carrega `st.attr`, `st.level`, `st.atk` em `$s`/pilha logo depois de `duel_field_stats(p, z, &st)`, o fonte tinha `atk = st.atk; attr = st.attr; level = st.level;`; usar `st.x` direto muda a alocação inteira (700 palavras de diferença contra 180). A ordem das declarações decide os slots de spill (`ref`, `atk`).
- **`li v0,1; b fim; nop`** (atraso não preenchido) vem de `goto ok;` para um rótulo `ok: return 1;`; `return 1` direto põe o `li` no atraso. O teste `beqzl arg → fim; li v0,1` sai de `if (arg != 0) { …; goto fail; } ok: return 1;`.
- **`(unsigned short)((unsigned char)p | (unsigned char)z << 8)`** gera `andi z; sll; andi p; or v0,v1,v0` (registros na ordem do original); com `& 0xFF` os registros trocam.
- **Grupos de `case` com o mesmo corpo**: `case A: case B: x = 1000; break;` testa B com `beql` + atraso e A com `beq` para o corpo; dois `case` separados com corpos iguais dobram os dois em `beql`.
- **`switch` de um caso só** (`duel_can_attack_target`): `beql x,K → corpo; b depois` (o teste verdadeiro desvia, o falso salta) é `switch (x) { case K: …; break; }`; `if (x == K)` ou `if (x == K && …)` gera `bnel` para depois.
- **Resto da função dentro de `if (arg != 0) { … } return 1;`**: o `beqzl arg → fim; li v0,1` e o `bgtz … → li v0,1` sem atraso preenchido no fim vêm do `return 1` compartilhado depois do bloco; `if (arg == 0) return 1;` no meio gera `bnezl` + `b`.
- **`if (a == 0 || f(b) == 0) return 0;`** gera `beqzl a → fim; move v0,zero` e o segundo teste com bloco `move v0,zero; b fim; nop`; dois `if` separados geram `bnezl`.
- **Variáveis de laço locais ao `case`** (`duel_direct_attack_kind`): quando cada laço de um `switch` usa registros diferentes (a0/a1 trocados, `$s` em outra ordem), cada caso declarava as suas: `case X: { int j; int all; … }` (as chaves fecham antes do próximo rótulo; a queda continua valendo). Variáveis da função inteira compartilhadas pelos laços dão a alocação errada.
- **`sltu; xori; bnezl` dentro de um laço de busca** é `if (!(!slot.card.id)) { all = 0; break; }` (dupla negação que o compilador não simplifica; provavelmente uma macro de "zona vazia"). A flag começa em `a0` reaproveitando o `li a0,1` da constante de `1 - p`.
- **`beqzl faceup → fora; all = 0`** num laço com dois testes é `if (id != 0 && (faceup == 0 || atk < X)) { all = 0; break; }` (um `||`); dois `if` aninhados invertem o desvio.
- **`if (a() || b()) return 1;` dentro de um `case`** (`duel_slot_eef84`): gera `bnel → fim, li v0,1` para o primeiro e o bloco `li v0,1; b fim; nop` (atraso vazio) para o segundo; dois `if` separados geram `beqzl` e atrasos preenchidos.
- **Atualizar um campo duas vezes sem ponteiro local** (`duel_mark_attacked`): `slot.flags |= A; slot.flags |= 1 << (slot.flags >> 22 & 1 ? 23 : 22);` direto deixa o endereço em `a2` e gera o ternário com `beqzl … li v1,22`; com `unsigned int *f` local o compilador usa base + deslocamento 0x40.
- **Testes de bit aninhados com um `return 0` só no fim** (`duel_slot_ref`, `duel_slot_immunity`): `bnel bit → fim, v0=0` seguido de `bnez bit2 → bloco "move v0,zero"` vem de `if (!(f >> 5 & 1) && !(f >> 1 & 1)) { switch … } return 0;` depois dos `return 0` antecipados; e `bnezl → fim, v0=r` de `if (f() == 0) { … } return r;`.
- **`||` de chamada em `if (tipo == X || (z >= 5 && z < 10 && g(id))) return h(...); return 0;`** (`duel_act_immune`) reproduz `bnezl → fim, move v0,zero` para o primeiro limite e o bloco `return 0` compartilhado para os outros.
- **`DuelAct` com bitfields de `unsigned char`** (`include/duel.h`): `a->player` (1 bit) e `a->zone` (5 bits, `sll 26; srl 27`) como bitfields; `a->player & 1` sobre o bitfield gera um `andi` a mais. O local `DuelAct a = { 0 };` gera o laço de zeragem byte a byte do original (`duel_card_can_affect`).
- **`int x = cond || !f(id);`** gera `x = 1; if (cond) pula; v = !f(); if (v) pula; x = 0` (`sltu; xori; bnez` seguido de `move sN,zero`), forma vista em `duel_act_can_affect` (que segue em asm porque o `st` anterior, materializado em `a0` no original, é fundido nos desvios pelo compilador).
- **`if (x > 4)` contra `if (x >= 5)`** (`duel_field_act`): o primeiro gera `slti at,x,5; bnez at → fora`, o segundo `slti v0` (o resultado vira valor); casar o registro `at`/`v0` do `slti` é escolher entre as duas grafias.
- **Ponteiro do contador como expressão separada** (`duel_grave_add`, `duel_zone_f_add`): `int p = c->owner & 1; DuelCard *dst = &duel.players[p].grave[duel.players[p].n_grave]; int id = c->id;` e depois `duel.players[p].n_grave++` reproduz o `&n_grave` com o símbolo deslocado (`D_08915E70`) separado da base da pilha; o `& 1` no bitfield `owner` vira `sll 26; ext 31,1`; o `(unsigned short)id` na chamada gera o `andi 0xffff`. Um índice separado do laço (`for (j = i; …)`) mantém `i` em `a1` (`duel_grave_remove`).
- **Ordem dos zeramentos antes do laço** (`duel_grave_count_monsters`): quando o original zera o acumulador antes do `beqz` e o índice no atraso (o contrário do que `int i; int n = 0; for (i = 0; …)` dá), escrever `p &= 1; i = 0; n = 0; for (; …)`; o `perm_decls`/permutação de comandos acha a ordem.
- **`switch` sobre o byte baixo** (`duel_zone_f_count_monsters`): `switch ((unsigned char)marks[i]) { case 0x80: break; case 0x40: default: … }` gera `lbu` e os dois testes (0x40 com `beql` para o corpo do `default`).
- **Limite inferior por ternário** (`duel_list_card_level`): `bgtz x → L; nop; b L; li x,1` é `x = x <= 0 ? 1 : x;` (ou `x < 1 ? 1 : x`); `if (x <= 0) x = 1;` e `x > 0 ? x : 1` geram `blezl`.
- **Valor da comparação reaproveitado como argumento** (`duel_list_card_level`): `duel_is_cur_card()` chamada com `a0` ainda valendo o id do slot (já comparado com 0x150B) vem de `duel_is_cur_card(slot.card.id)` no fonte, não da constante.
- **Bits 14 e 15 de `DuelCard`** (`b14`, `b15`, antes `f14 : 2`): `lbu +1; sll 25` testa o bit 14 (`duel_grave_card_usable`).
- **Tabela de salto de `switch` no `@data`** (`stat_reason.c`): um `switch` denso (casos 6-13) gera `jtbl_XXXX` no `.data` do objeto; basta declarar `// @data` com o intervalo exato da tabela (0x20 bytes para 8 casos) e o build casa os endereços dos casos. A ordem dos corpos segue o fonte (os casos 10-13 antes dos 6-7 no original).
- **Índice de lista de efeitos como `unsigned int`** (`duel_effect_reason`): com `unsigned short e` o compilador repete `andi 0xffff` ao indexar; o original carrega `next` com `lhu` e usa direto. Em `duel_slot_markers` a ordem `DuelStats st; DuelStats st2;` decide qual fica em sp+0x28 e qual em sp+0x54.
- **`ext` em vez de `srl`/`sra`** (`duel_field_level`): `ext rd,rs,4,8` depois de `andi 0xF0` vem de `(unsigned char)((x & 0xF0) >> 4)`; `ext 8,8` depois de `andi 0xFFFF` de `(unsigned char)((r & 0xFFFF) >> 8)`. O `>> 8 & 0xFF` sem o cast gera `srl`/`sra`.
- **Id lido como `int` com cast nas chamadas** (`duel_field_level`, caso 10): `int cid = slot.card.id; if (cid != 0 && …) { card_get_type((unsigned short)cid); switch ((unsigned short)cid) … }` mantém o id em `v1` para o teste e só copia para `$s0` depois; um `unsigned short cid` declarado dentro do `if` vai direto para `$s0`.
- **Variável de laço reaproveitada** (`duel_field_type_ex`): o jogador da origem de cada efeito (`src & 0xFF`) mora no mesmo `$s3` que o `q` do laço anterior: o fonte reaproveita `q = src & 0xFF;` em vez de declarar `player`. A zona (`ext 8,8`) é `unsigned int`, não `unsigned short` (que repete `andi 0xffff` ao indexar).
- **Ordem das declarações com inicializadores que chamam funções**: `int best = 0;` declarado antes de `int id = …; unsigned int imm = f(); …` põe o `move s2,zero` antes da primeira chamada, como no original; achado por força bruta das permutações das declarações (144 variantes, uma dá 0).
- **`check_file` mascara chamadas para funções do mesmo arquivo**: um `jal` local aparece como `jal 0x0` e pode esconder uma diferença de uma instrução só vista no build completo (`duel_field_attr_is`: `and v0,v0,v1` no original contra `and v0,v1,v0`; nenhuma grafia de `f() & 1 << k` inverteu os operandos, ficou em asm).
- **Handlers de efeito de carta** (`effects_a.c` em diante): recebem o `DuelAct` e retornam o próximo passo da corrente (`duel_step`, 0x7A-0x80) ou 0; os testes de `duel_step` são `switch` com os casos em ordem decrescente (0x80 primeiro), e um caso que retorna o valor de comparação de outro (`return 0x7E` no caso 0x7F) reaproveita o registro da constante.
- **`(x & 0xFF) - 1` sobre um `unsigned char`** gera o `andi 0xff` redundante antes do `addiu -1` (`duel_eff_f82b8`); `(unsigned char)x - 1` ou uma variável local não geram.
- **Operandos de `xor` em `q != a->player`** (`duel_eff_f8564`): com `q = duel.turn_player ^ i` numa variável local o compilador gera `xor a2,a0,v0` como o original.
- **Retorno antecipado que vira o caminho do desvio** (handlers): o original prefere `beqzl cond → fim, li v0,K` com o resto em queda; isso sai de `if (cond != 0) { …; return X; } return K;` (o `return K` depois do bloco), não de `if (cond == 0) return K;` no topo. Valores devolvidos sem `li` (o registro já tem a constante de um teste do `switch`, ex.: `return 0x7D` num caso 0x7F) também indicam o caminho.
- **Tipo dos parâmetros pelos call sites**: se um call site carrega a variável com `lhu` e outro passa uma `int` com `lw` sem máscara, o parâmetro é `int` e a primeira variável é `unsigned short` (`Duel.unk3830`).
- **Valor comparado reaproveitado como argumento** (`duel_eff_f9024`): `ext a1,…; li v1,14; bnel a1,v1` e depois a chamada com `a1` intacto vem de `zone = …; if (zone == 14) f(p, zone, …)` (a variável, não a constante 14).
- **Tabela de salto de função mantida em asm**: se a função com `switch` denso ficar em `@asm`, o `@data` da tabela não pode ser declarado no `.c` (o C sob `NON_MATCHING` não a emite e o link falha com `undefined reference to jtbl_…`).
- **Handlers com dois parâmetros** (`effects_d.c`): quando o handler repassa o segundo argumento ao handler genérico (`return duel_0888229C(a, b);`), o original não toca em `a1` no corpo; declarar só `DuelAct *a` faz o compilador usar `a1` como temporário. `if (x != 0) return f(a, b); return 0;` gera `beqzl x → fim, v0=0` com a chamada em queda.
- **Zona do `DuelAct` como `unsigned char`** (`unsigned char z = a->zone;`) gera o `andi 0xff` depois do `srl` do bitfield, como nos handlers originais.
- **`DuelAct` +0x02 como bitfields de `unsigned short`** (`player:1, zone:5, kind:6, …`): o tipo de ativação (`(u16 & 0xfff) >> 6`) cruza os dois bytes; com `unsigned short` os acessos de `player`/`zone` continuam `lbu` e o de `kind` sai `lhu; sll 20; srl 26`.
- **Atribuição em cadeia de bitfields** (`duel_eff_fa6e4`): `a->b4_3 = a->b4_2 = a->b4_1 = 1;` gera o `sll; ext` que relê o bit recém-escrito para o próximo campo, como no original; três atribuições separadas de `1` não.
- **Ponto aberto nos handlers**: em alguns handlers o original calcula a zona (`(t >> 8) & 0xFF`) antes do jogador; nenhuma grafia testada reproduziu a ordem, e esses ficaram em asm (`duel_eff_fa288`, `fa6e4`, `fa800`). O `1` de `1 - player` em `a2`/`a3` era um argumento `1` a mais da chamada seguinte (ver a regra do argumento `1` reaproveitado); `f9ed0` e `fa5c8` saíram assim.
- **Tipos das variáveis intermediárias pelos `andi` nas chamadas** (`effects_h.c`): `andi a3,s0,0xffff` só no momento da chamada indica variável `int` e parâmetro `unsigned short`; um `unsigned short` local gera o `andi` já na carga. Um caminho com um único `return 0` no fim (blocos `if/else` aninhados) reproduz os desvios `beqz → bloco "move v0,zero"` do original melhor que retornos antecipados.

- **Guarda e chamada numa só condição** (`duel_eff_fb81c`): `if (a->b4_2 == 0 && f(a, 0, 0)) {...} return 0x7F;` gera o `bnezl → li v0,0x7F` do original; o `if (a->b4_2) return 0x7F;` separado inverte o desvio. Guardar `t & 0xFF` numa variável própria antes da zona reproduz o `andi a1` logo depois da chamada. Em contadores, declarar o índice antes do acumulador (`unsigned int i; int n;`) troca os registradores `s1`/`s2` para os do original.

- **Argumentos que o original não passa** (`duel_eff_fbcd4`): quando o registrador de um argumento guarda um valor velho (o quociente de `link / 10` em `a2`), a chamada tem menos argumentos que o protótipo usado em outros arquivos; declarar a função em K&R (`void duel_088CC178();`) no arquivo. Handlers que repassam `b` a outro handler (`return f(a, b);`) mantêm `a1` livre e trocam os registradores de todo o corpo, por isso o protótipo `(DuelAct *a, int b)` vale mesmo quando o próprio handler não usa `b`. Um `switch` de um só `case` com `default` reproduz `beql K → corpo; b default; nop`, que o `if/else` não reproduz.

- **`DuelAct` +0x14 como `DuelSrc`** (`effects_k.c`): o mesmo halfword é lido como `uid:9, player:1, zone:4` (carta que causou a ação) num `union` anônimo com os campos de byte antigos (`b14`, `b15_*`). Um ponteiro local `DuelSrc *s = &a->src;` reproduz o `addiu s1,a0,0x14` e as releituras por `s1` do original (`duel_eff_fc4c8`). `MIN(f(), g())` com chamadas reproduz as duas chamadas repetidas do original (`duel_eff_fc534`). Quando o original não usa `a1` mas o handler não repassa `b` a um handler, procurar o callee que recebe `b` (`duel_0886CE90(a, b)`). O tipo do parâmetro do callee muda a ordem das cargas antes da chamada: `int uid` em vez de `unsigned short` (`duel_088E6628`).

- **O `1` de `1 - player` num registrador de argumento é um argumento `1`** (`duel_eff_fced0`, `fd058`): quando o original carrega `li a3,1` e faz `subu a0,a3,v1`, a chamada tem um quarto argumento igual a 1 e o compilador reaproveita o registrador já carregado; com o protótipo certo (`duel_088C7478(q, i, &hand[i], 1)`) a ordem sai igual. `!!f()` como condição gera o `sltu v0,zero,v0; xori v0,v0,1; bnezl` do original (`duel_eff_fca90`). Um `switch` com o `default: return K;` antes dos `case` evita o trampolim `b fim` que o `return K;` depois do `switch` gera. O tipo do último parâmetro (`int` em vez de `unsigned short`) muda o ponto em que o argumento anterior é calculado.

- **Registradores de argumento preservados apontam a assinatura** (`duel_eff_f84a4`, `fa920`): quando o original evita `a0`/`a1` num trecho sem chamadas e usa `a2`, o handler recebe `(DuelAct *a, int b)` e passa os dois a uma chamada adiante (`duel_08883FBC(a, b)`, `duel_0886CE38(a, b)`). Uma faixa `@asm` pode esconder uma função curta sem nome depois da que foi decompilada (`duel_eff_f8544` dentro da antiga faixa de `f84a4`): conferir o tamanho da função contra a faixa antes de tirar o `@asm`, senão o link falha com `func_<ADDR>` indefinido. Uma função tirada do asm que gera tabela de saltos precisa da faixa `@data` da tabela no arquivo (`effects_c.c`), senão a tabela vai para `.rodata` e desloca todo o `.data`.

- **Resultado de chamada num local antes da expressão** (`duel_eff_fd560`): `int c = duel_field_controller(...); f(..., a->uid * 8 + c * 4 + 1);` reproduz o `addu v0,v1,v0` (termo do uid primeiro) do original; com a chamada dentro da expressão o mwcc soma na ordem inversa. Um `if (step == 0x80) {...}` cujo outro caminho o original põe depois do corpo é um `switch (duel_step) { case 0x80: …; default: … }` (`duel_eff_fd4c8`). Nomes `ehsys_<ADDR>` no C exportado do Ghidra são imports do BOOT resolvidos pelo endereço do BOOT, não funções locais: o alvo real é o stub em `0x08903…` (`card_is_attribute9`), e o `check_file` não pega o erro porque mascara os `jal`.

- **Testes encadeados num só `&&`** (`duel_eff_fd690`, `fdaf8`): o mwcc encadeia o primeiro teste que falha direto para o fim (`beqzl … move v0,zero`) e manda os seguintes para um bloco `move v0,zero; b fim; nop`. Quando o original tem o primeiro teste encadeado e os outros no bloco, todos estão no mesmo `if (A && B && C) {…} return 0;`; ifs aninhados ou um `if (!A) return 0;` separado não reproduzem. **XOR com o jogador do turno** (`duel_eff_fab50`, `fdd6c`): `p = duel_turn_player; p ^= duel_w_089148FC;` carrega o jogador do turno primeiro e reproduz o `xor a2,a2,a1` do original; `p = duel_turn_player ^ duel_w_089148FC` troca os operandos. **`DuelAct` +0x14 como `int idx`** (índice em `duel.list`, lido com `lw`) no mesmo `union` de `DuelSrc`.

- **Valor de retorno pré-carregado** (`duel_eff_fde68`): um `case` que devolve o que está em `v0` sem carregar nada (`bnel … corpo; b fim; nop`) é um `int r = 0x7C;` declarado no topo do handler, que o mwcc põe em `v0` junto com a constante da primeira comparação do `switch`; `if (x == 0) return r;` reproduz o desvio. Um `?:` entre duas constantes no fim de um passo sai como `if (c) r = A; else r = B; return r;`. Para que um teste com `duel_act_target` no meio ainda fique no mesmo `&&`, a chamada e os campos entram como expressão vírgula (`(t = duel_act_target(a, 0), q = t & 0xFF, …, duel_0884E440(a, q, z) != 0)`).

- **Ponteiro local para um buffer da pilha** (`duel_msg_post`): o original guarda `&m` num `$s` (`addiu s1,sp,0x20` no delay slot da primeira chamada) e o usa no `memset`/`memcpy`/envio, enquanto os campos são gravados direto pelo `sp`; isso sai com `DuelNetMsg *p = &m;` atribuído antes da primeira chamada. `g->slot[k].campo` gera `addu v0,v0,base`; o original soma a base primeiro (`addu v0,base,v0`), o que só saiu com a conta em bytes (`*(unsigned short *)((char *)g + k * 0x188 + 0x128)`).

- **Valor 0/1 sem `sltiu` encadeado** (`duel_5250_in_range`): `int r = 0; … if (x <= 6) goto end; if (x >= 0x49) goto end; r = 1; end: return r;` reproduz os dois desvios com `at` do original; `x >= 7 && x < 0x49` vira expressão booleana com `xori`, e a ordem de declaração (`int r = 0;` antes de `x`) decide o registrador de `x`. Um `if (v > 0) {…}` cujo outro caminho só devolve `v` sai com `if (v <= 0) return v; return …;` (`duel_088FE810`). Bits lidos de uma palavra antes do teste: guardar o segundo bit num local (`unsigned int b24 = f >> 24 & 1; r = (f & 1) || b24;`) para o `ext` vir antes do `andi` (`duel_player_protected`).

- **Endereço base de chamada mais índice** (`duel_save_once_cc`, `duel_save_once_120`): o original soma o índice antes da base (`addu v0,s0,v0`) quando a conta é feita em inteiro (`(unsigned char *)((int)base + i) + 0xCC`); `base + i + 0xCC` em ponteiro soma na ordem inversa e `&base[i + 0xCC]` soma a constante primeiro. Um `if (*p == 0) { *p = 1; return 1; } return 0;` reproduz o `bnezl … move v0,zero` com o `li v0,1` reaproveitado no `sb`. Um id lido com `lhu` e comparado sem `andi` é `int` (`duel_deck_stats`).

- **Fim da libduel_eng** (`duel_result.c`, `duel_finish.c`): as funções grandes de fim de duelo (recordes, bônus, títulos, `duel_finish`) têm um `switch` por índice num laço de 40 a 118 casos; o C sai do mesmo tamanho ou quase, mas o mwcc distribui os `$s` de outro jeito e nenhuma ordem de declaração muda isso (permutações completas testadas), então ficaram em asm com o C sob `NON_MATCHING`. A tabela de saltos dessas funções fica no asm (sem `@data`). Numa busca binária, comparar o campo lido num `int` local (`int v = c->id; if (v == key)`) dá a ordem de operandos do original.

- **Laços de zona com `pl` fora do laço** (`field_find.c`): `DuelPlayer *pl = &duel.players[p & 1];` antes do laço e `pl->field[i]` dentro reproduzem o ponteiro de slot `pl + 5 * 0x14` que o mwcc cria para laços de 5 a 10; um `DuelSlot *s` declarado dentro do laço não. O resultado de `field_get_card` num local (`int c = field_get_card(p, i); if (c == id …)`) dá a ordem `bnel v0,id` do original. Um `if (a == 0) return b; if (b == 0) return a; return MIN(a, b);` reproduz o mínimo não nulo (`duel_min_order_both`). Um teste com `card_is_monster` cujo ramo de monstros vem primeiro no código é `if (card_is_monster(id) != 0) {…} else {…}`.

- **`!(x) != 0` como condição** (`duel_slot_faceup_live`, `duel_slot_e8170`): gera o `sltu v,zero,x; xori v,v,1; beqz` do original, que `!x` (que dá `bnez`) e `x == 0` não geram. Um teste em dois tempos (`ok = 1;` e depois `if (ok && …) r = 1;`) reproduz o `move s1,a0` com o `1` do `sllv` reaproveitado. O contador de bit de zona (`1 << (p * 16 + i)`) que o original mantém num `$s` próprio só sai com uma variável explícita (`for (i = 0, b = p << 4; …; i++, b++)`), e mesmo assim o mwcc troca os registradores do contador e do ponteiro de slot; essas funções ficaram em asm (`field_find.c`, `field_active.c`). **`DuelSpecAct`** (0x38, `duel_special.act[2]` em +0x2C): id e uid da carta especial ativada.

- **Localização empacotada** (`duel_card_locate`): o original monta `jogador | zona << 8` num `unsigned short` antes de juntar o índice (`(unsigned short)((p & 0xFF) | 0xE00) | (unsigned short)i << 16`), e o laço das duas cartas especiais reaproveita o índice `i` dos outros laços. O índice do Ghidra pode omitir funções de 8 bytes (`j alvo; li a2,K`) entre duas funções: conferir os endereços da faixa contra o desmonte cru antes de dar o arquivo por completo (`duel_slot_counter_1513`), senão o `.text` encolhe 8 bytes e tudo depois se desloca. **`duel.list[512]`** (0x800 bytes em +0x1F6C, até os efeitos).

- **`field_get_card`** (`piles.c`): o `switch (id)` sobre os ids especiais (`case 0x19A6`, `0x19BC`, `0x1A74`) reproduz os `beql` do original, e `if (id == -1 || duel_card_protected(id, -1)) return 0x1A74;` reaproveita o `-1` da comparação como segundo argumento. Contadores de pilha: a ordem de inicialização no `for` decide quem vai no delay slot do primeiro teste (`for (i = 0, n = 0; …)` num caso, `for (n = 0, i = 0; …)` no outro).

- **Ordem dos `case` pela tabela de saltos** (`duel_card_put`): com tabela, os corpos saem na ordem do fonte e a tabela dá o endereço de cada um; ordenar as entradas por endereço dá a ordem dos `case` no fonte (aqui 0xC, 0xD, 0xE, 0xF, 0xB, `default`, 0x10). Um `if (z == 0xB || z == 0xD || z == 0xC)` que o original testa com `beql` em sequência é um `switch` com os três rótulos juntos; o `||` vira teste de faixa. Um índice somado em partes (`1 << (i + (zone + p * 16))`) evita que o mwcc reaproveite `zone + i` já calculado. Um ponteiro escolhido por `&&` direto no argumento (`f(a && b ? &x : &y)`) reproduz o `bne; beql; b` do original.

- **`DuelCard` com bitfields `unsigned int`** (`card_place.c`): a cópia de uma carta (`*dst = *src`) sai no original como `lwc1`/`swc1`, a cópia de um struct de 4 bytes alinhado a 4; com bitfields de `unsigned short` (alinhamento 2) o mwcc copia por halfwords. Trocar para `unsigned int` manteve todos os outros arquivos da libduel_eng iguais (o mwcc continua estreitando os acessos aos campos para `lhu`/`lbu`). As entradas de `duel.list[]` têm um contador de 2 bits nos bits 13–14 (`DuelListCard.placed`), acessado por um cast.

- **Lista de cartas como global própria** (`effect_list.c`): os acessos do original a `duel.list[uid]` com o deslocamento do campo dobrado no endereço (`addiu v0,v0,%lo(0x08917DCA)`) só saem com uma global separada no mesmo endereço (`extern DuelListCard duel_cards[512];`, símbolo `duel_cards = 0x08917DC8`); pelo membro `duel.list` o mwcc soma o deslocamento no `lhu`. As listas de efeitos são percorridas com `while (e != 0) { ef = &duel.effects[e]; e = ef->next; if (…) return ef; } return 0;`; o índice devolvido (`duel_slot_effect_index`) fica na variável do laço com o próximo num local. O nibble alto de `DuelEffect.kind` lido como bitfield (`kind_hi : 4`) dá o `sll 24; srl 28` do original.

- **Varreduras com chamada no corpo** (`effect_scan.c`): quando o laço chama `duel_effect_free(e)`, o original mantém `e` no argumento e o próximo num `$s` (`unsigned int next = ef->next; …; e = next;`), e um teste único de tipo é um `switch` de um `case` (o `if` sai com `bne` em vez de `beq; b`). Um bitfield decrementado sai como no original com `ef->kind_hi -= 1;` e não com `--`. A forma da comparação escolhe o registrador: `x >= 6` e `z < 12` usam `slti v`, `x > 5` e `z <= 11` usam `slti at`. Campos da fonte (`src & 0xFF`, `src >> 8 & 0xFF`) comparados como locais (`ez` antes de `ep`) dão o `ext` antes do `andi`; como índice de `duel.players[…].field[…]`, os casts `(unsigned char)src & 1` e `(unsigned char)(src >> 8)` dão o `andi 0xff; andi 1` do original. Um `case 0x175D:` isolado num `switch` reproduz o `beql id; b fim` de um teste de id; um retorno `unsigned short` aparece como `andi v0,0xffff` antes do `jr`. A ordem de declaração resolve a maior parte dos registradores.

- **`switch` grande por id sem tabela** (`effect_live.c`): o mwcc testa os `case` na ordem inversa do fonte, um grupo depois do outro, e põe os corpos na ordem do fonte; então os corpos ordenados por endereço dão a ordem dos grupos, e cada grupo lista seus rótulos na ordem inversa das comparações. A primeira comparação de cada grupo (na ordem do binário) é um `beql` para o corpo + 4 com a primeira instrução no delay slot; quando o corpo é só `v0 = K; b fim`, o `beql` vai direto ao epílogo e o rótulo pertence ao grupo do mesmo `K`. Ids que só fazem `break` também são comparados (desvio ao `return` depois do `switch`), e a posição dessa comparação na sequência diz onde o `case X: break;` fica no fonte, mesmo entre outros grupos. Um teste `if (x) return K; break;` sai com `beqz` para o fim do `switch`; um `?:` que sai com o desvio invertido se corrige trocando os ramos (`a != b ? 1 : 2`). Um `switch (zona)` denso com tabela precisa dos `case` vazios (`case 0x11: … break;`) para o mwcc gerar a tabela do original.

- **Verificações de regra** (`rules_check.c`): `return !f(…);` dá o `sltu; xori` do original (e não `xor; sltiu` de `f(…) == 0`). Uma cadeia de testes que só devolvem 0 ou 1 sai com `int r;` e `if … r = 0; else if (A && B) r = 0; … else r = 1; return r;`, e não com `return` em cada teste. Num grupo de `case`, só a primeira comparação no binário (o último rótulo do grupo no fonte) sai como `beql`; um `case 0xB:` testado com `beql` antes de outros quatro com `beq` está no mesmo grupo, como último rótulo. A escolha entre as duas cartas especiais é `(cond ? &duel_special.slot[0] : &duel_special.slot[1])->campo`, e o teste de faixa que deixa o caso especial no caminho direto é `if (z + i > 10) { … } return …;`. Bit de uma palavra lido com `ext` é `x >> 2 & 1`, não `(x & 7) >> 2`.

- **Passos de pedido** (`req_step.c`): um `switch (duel_req_step)` de um `case` só dá o `beqz … ; b fim` do original, que um `if (step == 0)` não dá. Um passo que só avança escreve `duel_req_step++` mesmo quando o valor é conhecido (`addiu v,v,1`). Um ponteiro para um campo escalar de `duel.players[p & 1]` com o deslocamento do campo dobrado no endereço da global (`addiu v1,v1,%lo(duel+0x14)`) sai com `(unsigned int *)((char *)&duel.players[0].n_grave + (p & 1) * sizeof(DuelPlayer))`. Dois caminhos que zeram a mesma flag sem compartilhar o bloco são `if (a) x = 0; else if (b) {…} else x = 0;`. Ponteiros para texto passados a `duel_wcscat` precisam de protótipo com ponteiro (com `int`, o `addiu` do endereço sai fora do delay slot). Os campos do pedido (`duel_req.id`, `.arg`, `.loc`, `.w`) que o original lê antes do teste do passo são locais declarados no topo na ordem em que ele os carrega. Globais logo depois do `Duel` (turno, fase, 0x089195FC…) são variáveis separadas no original: pelo struct o mwcc reordena loads e stores que o original não reordena (`duel_req_next_turn` usa `duel_turn`, `duel_phase`).

- **Condições de ativação** (`act_cond.c`): um teste final que devolve 1 com o caminho de 0 em bloco próprio sai com `if (a && b) return 0; return 1;` (`a->zone > 10 && pick < 0`), não com dois `return 1`; um `if (x >= 2) return 2; return 0;` dá o `slti v; bnezl` que `if (x < 2) return 0; return 2;` não dá depois de outros testes. Um `if (!f()) return 0;` seguido do `return 1` comum reproduz o `bnezl v0 … li v0,1`. Funções que só repassam o segundo argumento (`(DuelAct *a, int b)`) precisam do parâmetro mesmo sem usá-lo, para o chamador não zerar `a1`. Antes de criar um arquivo, conferir as funções da faixa no asm dividido (os `glabel` de `asm/<m>/text_*.s`) ou no desmonte do ELF: o índice do Ghidra omite funções (`duel_hand_can_discard` em 0x0886CB68), e uma função esquecida dentro do `@range` some do link (`undefined reference`).

- **Campos do +0x14 do `DuelAct`** (`act_cond2.c`): quando o original guarda `a + 0x14` num `$s` e lê o campo dali (`addiu s0,a0,20; …; lhu v0,0(s0)`), o fonte tinha um ponteiro para esse campo declarado no topo (`unsigned short *src = (unsigned short *)&a->src;`). Uma cadeia em que só o primeiro teste devolve direto e os outros caem em blocos próprios (`if (k == 0x16) … else if (k == 2) …`) sai com `int r;` atribuído em cada ramo e um só `return r;`. Testes de bits soltos do +0x14 usam as visões `y` (bytes 0x15 e 0x16) e `x` (palavra) de duel.h.

- **Bloco `li K; b fim; nop` compartilhado** (`effects_zg.c`, `effects_zh.c`, `effects_zi.c`): quando vários testes que falham caem num mesmo `return K` no fim do `case`, o mwccpsp encadeia só o **primeiro** deles direto ao epílogo (`beqzl …, fim; li v0,K`) e os demais saltam sem likely (`beqz`/`bne` + `nop`) para um bloco `li v0,K; b fim; nop`. Para reproduzir, todos os caminhos de falha têm de chegar ao mesmo `return K` final: `if (A9008()) { …; if (E440()) { …; return 0x7F; } } return 0;` bate, e um `return 0;` interno a mais (depois do `if` de dentro) faz o segundo teste também virar `bnel` ao epílogo. Resolveu as funções com o teste da zona 0xE (`08892554`, `08893390`, `08894DE8`), `08891438` e `088918EC`.
- **Reuso de variável muda o registrador** (`08891438`, `08891F38`, `08892554`): quando duas variáveis do original trocam de `$s`/temporário e nenhuma ordem de declaração resolve, o original reaproveita uma variável já declarada para um valor novo (o alvo `t` recebe depois o id da carta; o contador `i` do primeiro laço vira o jogador do segundo). Testar a troca do nome nas linhas do trecho com as variáveis existentes.

- **Chamada a função `static` do mesmo arquivo** (`effects_0889A75C.c`, `effects_088ACCF8.c`, `effects_088A49F8.c`): o original mantém valores em `$a0`-`$a2` através de uma chamada a uma função vizinha que ele sabe não tocar nesses registradores. Isso só sai quando a chamada é `static` e definida no mesmo `.c` (`duel_0889B034`, `duel_088A6220`); com protótipo `extern` o compilador recarrega. `duel_088A8B94` é um desses casos e está em outro trecho: quatro funções de `effects_088ACCF8.c`/`effects_088AE378.c` ficam em asm até que ele entre no mesmo arquivo.
- **Tipo dos parâmetros do callee muda a alocação** (`effects_088A1904.c`): `unsigned short id` contra `int id` em `duel_08832880`/`duel_08832894` decide se `a` fica em `$a0` e em que ordem os argumentos são calculados. Testar o tipo do protótipo antes de mexer no corpo.
- **`switch` de um `case` e grupos de ids**: `switch (a->id) { case K: return 1; }` dá o `beql` encadeado que o `if` não dá; `t == 10 || t == 0x10 || t == 0xB` sai de `switch (t) { case 0xB: case 0x10: case 10: … }`; uma faixa `(unsigned int)(k - 0x12) < 2` dá `addiu`/`sltiu`, e `case 0x12: case 0x13:` dá a cadeia de `beq`.
- **Argumento que parece não usado**: quando `$a1`/`$a2`/`$t0` já têm um valor na chamada sem motivo aparente, o original o passa (`duel_088C7810(1 - p, 1)`, `duel_088CAB04(q, i, 1)`, `duel_088C87A8(…, a->player)`); handlers que não tocam `$a1` são `(DuelAct *a, int b)` e repassam `b`. Função sem valor de retorno tem de ser `void` (senão `$v0` difere no fim).
- **Laços seguidos e índices**: reaproveitar a variável de um laço no seguinte (`z` do laço das zonas como índice do cemitério) e escrever `i < (unsigned int)n_d` quando o original compara com `sltu`; um limite lido uma vez só é uma local (`n = n_hand; for (i = 0; i < n; i++)`). `perm_locals.py` só permuta as declarações antes da primeira linha em branco: deixar ali só as 4-6 duvidosas.
- **Último `case` que cai no epílogo**: terminar com `break` em vez de `return 0` (um `default: return 0;` explícito cria um bloco a mais).
- **Contador de passo mantido em registrador** (`ai_0883F0DC.c`): `for (; (i = duel_w_08919608) < 10; duel_w_08919608++)` com `unsigned int i` mantém o valor carregado no laço como o original.
- **`z << 16` sem redução de força** (`ai_0883F0DC.c`, `ai_08853340.c`): `(unsigned int)z << 16 & 0x1F0000` impede o mwcc de trocar o deslocamento por um contador `+0x10000` dentro do laço.
- **`if (A == K1 || A == K2)` em `beq` separados** (`ai_08834734.c`): sai de um `switch` com grupo de `case`; `addiu v1,v1,-K` seguido de comparações pequenas é `switch (x - K)`.
- **Leituras antes dos stores** (`ai_08836868.c`): o mwcc não sobe um load acima de um store em global; a instrução que lê (`duel_atk_zone = a + b;`) vem antes dos `= 0`.
- **Símbolo+deslocamento dobrado no `lui/addiu`** (`ai_08837500.c`): `*(T *)((char *)&duel.players[0].field[0].f + (p & 1) * 0xFAC + z * 20)` com constantes `int`; `sizeof` quebra o CSE.
- **`return x < K ? 1 : 0;` num `case`** (`ai_0884F038.c`): o `return x < K;` puro divide um `b fim` com o retorno antecipado.
- **Grupo com desvio direto ao epílogo** (`ai_08853CE8.c`): num `switch` grande por id, um teste que salta direto ao `fim` (`beql … fim`) é o primeiro de um grupo cujo corpo é `return K`; junte-o ao grupo.
- **Chamada sem argumentos a função K&R** (`card_desc.c`, `duel_0884ED08`): o original chama sem passar `$a0`; a definição K&R e o chamador no mesmo arquivo do `static` mantêm `a` em `$t1`.
- **`default:` primeiro no `switch`** (`ai_0886191C.c`, `duel_08861CB4`) põe o corpo do default logo depois dos testes; `z > 4` dá `slti at` onde `z >= 5` dá `slti v0`.
- **Endereço de global mantido em `$s0`** (`html_viewer.c`): `T *const p = &g;` (o `const` do ponteiro, como em `ehfile_term`) impede o mwcc de rematerializar o `lui/addiu` nos stores do primeiro bloco; sem `const`, ele só usa o registrador depois do primeiro desvio. Também funciona `(T *)(char *)&g`.
- **Constante do `switch` reaproveitada como argumento** (`html_viewer_update`): `li a0,2; beq v0,a0` seguido de `jal sceUtilityHtmlViewerUpdate` significa que a chamada recebe 2 (`sceUtilityHtmlViewerUpdate(2)`, assinatura real do SDK). Se o registrador de uma constante de comparação parecer estranho, confira a lista de parâmetros real do callee.
- **Tabela do `switch` antes das strings no `.data`** (`html_url.c`): o mwcc emite os literais da função antes da jtbl. Para sair jtbl → strings, defina as strings como `static const char x[N] = "..."` **depois** da função (com uma declaração `static const char x[N];` antes); tudo vai para `.rodata`, na ordem jtbl → arrays.
- **Teste do resultado de chamada em `$s` ou em `$v0`** (`html_net.c`): `r = f(); if (r < 0) …` copia para `$s0` antes de testar (`move s0,v0; bgez s0`); `if ((r = f()) < 0)` testa `$v0`. No último teste antes de um `return r` comum, `if (r < 0) { g(); return r; } return r;` evita o `bgezl … move v0,s0`.
- **Valor recalculado no original** (`tlist_draw_scrollbar`, `drec_draw_scrollbar`): quando o original refaz uma conta (`move v0,s8; subu v0,v0,s0`), escreva a expressão de novo (`h - 2 - len`) em vez de reaproveitar a variável (`track - len`); o reaproveitamento cria um temporário a mais e derruba outro valor para a pilha.
- **Uma variável por chamada** (`period_up`/`period_down` nas barras de rolagem): o mesmo valor lido de novo antes de cada chamada, em variáveis separadas, corrige a troca de `$s` entre as duas chamadas.
- **Ponteiro que anda vs. índice** (`drec_build`): troca de `$s` entre um ponteiro de tabela e um contador em laços quase iguais vem de `p->x` com `p++` contra `tab[i].x`; teste cada laço nas duas formas (64 combinações resolveram as três abas). `for (i = 0, p = tab; …; p++, i++)` põe o `addiu` do ponteiro depois do zeramento.
- **Cópia morta depois de `bnezl …; b; move`** (`tlist_draw`, `duelrecord_draw`, `cardinfo_draw`): o original deixa uma cópia da primeira instrução do ramo que o mwcc move para o delay slot; nenhuma das ~80 variantes testadas (acessor inline, ternário, goto, switch, tipos do índice) nem os builds 134-219 do mwccpsp reproduzem. Em teste isolado só apareceu com `return e;` num else interno (`heap_find_entry`). Problema aberto.
- **Problema aberto:** o `lhu` de `a->kind` antes de `if (a->kind == 0x23) return 1;` sai escalonado diferente no prólogo (`duel_08856860`, `duel_08858440`, `duel_08858E2C`, `duel_08870E94`).
- **Diferença grande costuma ser forma, não registrador** (BOOT `heap.c`, `font_text.c`, `menu_open`): compare com o original ignorando os registradores e reescreva o C a partir do asm; `heap_*` foi de 286 palavras a 0 assim.
- **`li`/`move` morto entre testes** é a constante de um grupo `case K: default:` (`switch (region_get()) { case 1: default: A; break; case 0: B; break; }`).
- **Ramo com temporários próprios** (`heap_relocate_table`): declarar `HeapEnt *src, *dst;` dentro do `else if` dá ao laço de cópia registradores diferentes dos da função.
- **Booleano gravado por ramo** (`li s0,1` no delay slot, depois `move s0,zero`): `more = 1; if (cond) more = 0;`.
- **Valor cru para a chamada, mascarado só nos testes** (`font_draw_wtext_simple`): `int c` passado direto e comparado como `(unsigned short)c`.
- **`srl` em vez de `sra` numa metade unsigned short**: `(int)(x / 2u)`.
- **Laço curto que não pode desenrolar**: `if (h > 0) { k = 0; do n += 2; while ((k += 8) < h); }`.
- **`slt at` contra variável**: escreva a comparação ao contrário (`tw + 0x40 > w`); `w < tw + 0x40` cria um temporário.
- **Dois blocos `return 1` de um `switch` de estado**: `if (i != -1) { switch (s) { case 2: case 4: return 1; default: return 0; } } return 0;`.
- **Array na pilha 4 bytes fora**: `unsigned char buf[0x200] __attribute__((aligned(8)));`.
- **Constante como segundo operando de `mul.s`** (`tms_visible`): o mwcc põe o literal primeiro; passe-o por um inline (`static inline float f(float x, float k) { return sqrtf(x * k); }` chamado com `0.25f`).
- **Tempo de quadro a partir do fps** (`particle.c`): `int fps = gfx_get_state()->fps; float dt = n * (1.0f / fps);` reproduz o `cvt.s.w` no lugar; a conta inline não.
- **Ordem dos operandos de `or`** (`ehf_cmd_pool`): só uma variável fixa a soma à esquerda: `size = n * sizeof(T) + 0x10; return size | flag;`.
- **Ordem de cópias de struct** (`camera_reset`): com `Vec4 pos, target, up` declarados nessa ordem, atribuir `up`, `target`, `pos` reproduz as cópias intercaladas.
- **Posição de um parâmetro float** (`anim_blend`): onde o float fica entre os ponteiros decide quando o `mov.s $f12` entra no prólogo; teste todas as posições.
- **Índice em vez de ponteiros de chave** (`anim_eval_track_packed`): `v[lo * 4 + k]` em vez de `p0 = v + lo * 4`; uma constante copiada por um local (`Vec4 id = anim_quat_id; *out = id;`) reproduz a cópia pela pilha.
- **`void *` convertido depois de outro local** (`ehf_cmd_emitter`): `EhfArg *a = …; EhfEmitter *e = inst;`.
- **Tipo do parâmetro do chamado decide a ordem dos loads dos argumentos** (`ai_0882*.c`): com vários globais como argumentos, `int` contra `unsigned int`/`unsigned short` no protótipo do chamado troca qual load vem primeiro e em que registrador (`int duel_host_call(int, int, unsigned int, int)`; `duel_088309F8(unsigned int, unsigned short, unsigned short)`).
- **Qual constante fica no ramo likely**: `if (c) return 0x800; return 0;` dá `beqzl c → 0`; o original com `bnezl c → 0x800` vem de `if (c == 0) return 0; return 0x800;`. Em `c ? A : B` o B fica no ramo likely.
- **Corpo inteiro dentro do `if`**: `if (f()) { …; return X; } return 0;` dá `beqzl v0,FIM; move v0,zero`; `if (!f()) return 0;` dá `bnezl` + `b`.
- **Clamp com ternário** (`effects_088B4560.c`): `x = v > 0xFFFF ? 0xFFFF : v;` dá `bnez at` + `nop` + `li`; `MIN()`, `if` e variável local não.
- **Contador logo depois de um array** (`req_088D28F8.c`): declarar o par como struct (`struct { DuelReq req; DuelLogEnt q[256]; unsigned int n; } duel_req;`) faz o mwcc reler `n` depois de cada store e dobrar `q[n].v[k]` em `sym+off`.
- **Máscara em dois passos**: `mask = 1 << a; mask |= 1 << b;`; a expressão única avalia o segundo termo primeiro.
- **`1 - p` escrito em cada uso** em vez de um local `q` dá o registrador do original para o oponente; o "terceiro argumento sumido" no Ghidra é o 1 que sobrou de `1 - p` (`duel_0881616C(1-p, mask, 1)`).
- **Dois nomes para o mesmo global**: quando arquivos diferentes enxergam o mesmo objeto com structs diferentes (`duel_summon`/`DuelSummon` e `duel_atk_rec`/`DuelAtkRec` em 0x08914A14), declare o segundo nome em `symbols/` como `type:data alias`; o `fix_ld` faz `PROVIDE` dele e o splat o ignora. Um `#define` com cast `(*(T *)&g)` muda o código gerado.
- **Armadilhas das ferramentas**: `func_asm.sh` esconde `lw`/`sw` de `$s` em `$sp`, inclusive recargas de spill (use `raw_asm.sh`); `check_file.py` ignora relocações, então campo errado (`n_hand` por `n_d`) ou `memcpy` (import da libehsys) no lugar de `duel_memcpy` (0x088FF0E8) só aparecem no `make check`; a ordem dos comandos no pseudocódigo do Ghidra não é a do fonte.
- **`switch` denso que só atribui** (`libduel_mgr`): `case 1: lp = 2000; break; …` dá a cadeia `beql K → fim; li v0,X`; a cadeia de `if`/`else` não.
- **Variável declarada dentro do bloco do `case`** (`case 5: { unsigned short mask; … }`) corrigiu a alocação de `$s` onde nenhuma ordem de declaração servia.
- **`&s->campo` deixado em dois `addiu`** vem de aritmética inteira: `#define SLOT_RECIPE(s) ((RecipeData *)((int)(s) + 0x80))`.
- **`addu` com o índice primeiro** para `&p->ent[i]`: acessor inline (`return &gs->slot[k];`) ou `(T *)p->ent + i`; `&p->ent[i]` troca os operandos.
- **Índice em anel**: `t = q->tail + 1; q->tail = t < 16 ? t : 0;` com `int t`; `if (t > 15) t = 0;` não bate.
- **Helpers de desenho**: `if (g == 0) return list; …; return f(...);` bate; `if (g != 0) { list = f(); } return list;` acrescenta `move s,v0; move v0,s`.
- **Ponto {x, y} de 4 bytes num registrador** (`libselect_card`, `liblimitlist`): parâmetro `int pos`, desempacotado com `short x = pos & 0xFFFF; short y = pos >> 16 & 0xFFFF;`; uma struct por valor vai para a pilha.
- **Valor externo gravado por ponteiro local força recarga depois da chamada**: `ScPack *p = f(1); p->data = sc.pack_a;` (`f(1)->data = sc.pack_a` mantém em `$s`).
- **Impedir o mwcc de dobrar `&global`**: `T *p = &((S *)(char *)&g)->pos[t];` mantém a base num registrador.
- **Cast na soma**: `x += (unsigned char)d;` com `int d` reproduz o `andi 0xff` tardio; `px = (px - step) & 0xFFFF` com `int px` dá o único `andi` de uma variável u16.
- **Tabelas que o original alinha a 16**: `__attribute__((aligned(16)))`, senão o `.data` sai curto.
- **Contagem regressiva no laço**: `t = -3 * i - 4` reduz para `a3 -= 3`; `-4 - i * 3` não.
- **Templates de funções que ficaram em asm** viram globais nomeados definidos no mesmo ponto do arquivo; rótulos internos que o asm ainda usa vão em `symbols/` como `D_<addr> = …; // type:data alias`.
- **Cópia morta depois de `beql; b`** apareceu também nos `*_draw` exportados de `libcardalbum`, `libcharalist`, `libconv_machine`, `liblimitlist` e `librecipe_viewer` (mesmo problema aberto de `tlist_draw`).
- **Módulos copiados** (`libdeck_swap`, `libdeck_tutorial`, partes de `libshop` e `libtitle`): boa parte do código é o mesmo fonte de `libselect_card`/`libdeck`/`libtutorial`. Mapear as funções por tamanho e palavras normalizadas (opcode mascarado + pares jal/hi-lo) contra o módulo já feito e copiar o C renomeando; a maioria bate sem mudança e as diferenças aparecem como diferença de tamanho.
- **`case K: break;` em vez de `return 0;`** num estado que só retorna mantém o `b <move v0,zero compartilhado>; nop` do original.
- **`w = cw = expr;`** dá duas cópias em registradores diferentes; `cw = w = expr` troca.
- **Constantes float não dobradas**: `neg.s`/`mul.s` sobre constante vêm de um local (`float h = 7.634f;`); o menos unário não é dobrado depois da propagação.
- **Escrever um campo e relê-lo** para o próximo mantém a extensão de sinal do original: `b->x = x; b->ix = b->x + 3;`.
- **Chamado mascara parâmetros `short` mas o chamador passa int**: defina o chamado com `short` e mantenha um protótipo K&R para os chamadores (`void text_enter();`).
- **Ordem das declarações de base muda a ordem dos `lui` no link**: `Title *const t = &title;` antes de `TPanel *p = &title.panel;`; o `check_file` não mostra, só o `diff_words` no ELF linkado.
- **Ternário para subtração condicional**: `r += b >= 3 ? b - 3 : b;` dá `bnez` + `nop`; `if (b >= 3) b -= 3;` dá `bnezl`.

- **Função `static` chamada de fora do arquivo** (`effects_088A8B94.c`): quando um helper precisa ser `static` para o chamador manter `$a0`-`$a2` (ver acima) mas também é chamado por asm ou por outro `.c`, a linha em `symbols/` leva `type:func static matched …`; `fix_ld.py` então emite um `PROVIDE` com o nome para os outros chamadores.
- **Definições K&R** (`effects_088A8B94.c`): uma função chamada com quantidades diferentes de argumentos por chamadores que batem é definida sem protótipo (`int f(a, b) DuelAct *a; int b; { … }`) e declarada `int f();`.
- **Recarga depois de store no `duel_chain`**: quando o original relê um campo depois de gravar em `duel_chain.uids`, `*(volatile unsigned int *)&campo` reproduz a recarga; acessar o mesmo objeto pelo nome do membro (`duel_chain.n_kinds`) também força a recarga que globais separados não forçam.
- **Lista de candidatos como struct** (`effects_088BC9E0.c`): `duel_088BFC64` só bateu com a lista em 0x08915258 declarada como uma struct (`n`, `cards[512]`, `zones[512]`); com globais separados o compilador não relê o contador.
- **gmodules: `switch` com faixas** (`libpassword`): o mwcc aceita `case 2 ... 9:`; um `switch` que vira poucas faixas sai como árvore de comparações (`bltz` + `slti 10`) em vez de jump table. Listar os casos um a um gera a tabela.
- **`switch` terminado em `return 0` sem `default:`** (`password_update`, `st_found`): bate; `default: return 0;` acrescenta um bloco.
- **`x *= 10; x += d[i];` em comandos separados** (`libpassword`) reproduz o laço desenrolado que começa com `0*10`; `x = x*10 + d[i]` dobra a conta e troca os operandos do `addu`.
- **Bitfield `--`/`++`** dá `addiu 255`/`addiu 1` + `andi`; `x = x - 1` dá `addiu -1`.
- **Função `inline` com `switch` repetida** (`liblabo`, `voicetest_row_count`): o original tem o mesmo `switch` duas vezes inline; `inline int f(unsigned short)` bate, `static` não é expandida e vai parar entre as tabelas.
- **Acessor inline com teste invertido** (`libduelrecord`, `drec_entry`): `if (i >= count[t]) return 0; return &e[t][i];` dá `slt v0` + `bnezl` + `b; move v0,zero`; a forma `<`, ternário ou macro dá `slt at` + `beqzl`.
- **Tabelas como structs de bitfields** (`libduelrecord`): `sll 16; srl 17` + `andi 1` vêm de `struct { unsigned short visible:1; text:15; }`; `>> 1` daria `ext`.
- **Clamps com `max`/`min` do Allegrex** (barras de rolagem de `libduelrecord`/`libtutoriallist`): `ALLEGREX_MAX(page*track/total, 10)`, `ALLEGREX_MIN(ALLEGREX_MAX(…, 0), track - len)`.
- **Ordem de literais e tabelas no `.data` de um gmodule:** a tabela global inicializada cujas strings vêm depois do literal de uma função é definida depois dessa função (`drec_files` depois de `duelrecord_init`); a jtbl sai primeiro quando o arquivo não emite `.data` antes dela, e as tabelas `static const` definidas depois da função vêm em seguida.
- **Mesma forma, código diferente entre funções** (`libtutoriallist`): `if (rows + h > 8) top++; else cursor++;` bateu em `tlist_input`, mas `tlist_build` precisou de `if (rows + h < 9) cursor++; else top++;`. Teste as duas orientações.
- **Variáveis importadas do BOOT (`.sceVstub`):** `rand3_seeds`/`rand3_slot` ficam no endereço 0 no ELF convertido (`lui 0; lw 0`). O `link_map` lê os vstubs e o `fix_ld` define cada uma com `PROVIDE(nome = 0)`, então o C as usa como `extern` normal. O objdiff ainda as conta como diferença de relocação (por isso a libpassword aparece com 32/33 no ByteMatch).
- **Exports de um gmodule renomeados:** os outros gmodules que os importam (a liblabo chama libpassword, libtutoriallist, libduelrecord, ...) passam a ver o nome novo na parte gerada do `symbols/`; o C que chamava `libX_ADDR` precisa do nome novo (`build/tmp/fix_xmod.py` troca pelo endereço) e o módulo chamador precisa de novo `make MODULE=<m> verify` para re-splitar.

## Código GCC como funções `asm` do mwcc

O SDK linkado no BOOT (libgu, newlib, libgcc fp-bit, libvfpu, libccc, libfpu, libdeflt, libsas/libwave; nomes recuperados pelos NIDs de export, `sha1(nome)`) foi compilado com GCC ou escrito à mão e não sai de C pelo mwcc. Cada função vira uma função `asm` do mwcc com o C portável ao lado:

```c
#ifdef __MWERKS__
asm void sceVfpuVector3Add(ScePspFVector3 *d, const ScePspFVector3 *a, const ScePspFVector3 *b) { ... }
#else
void sceVfpuVector3Add(...) { /* equivalente em C para o port */ }
#endif
```

- O corpo sai do objdump (`-z`, senão ele esconde palavras zero e parece que o mwcc descarta `nop`s; não descarta, e o padding depois do `jr` fica). Geradores (gitignored, cópias locais): `build/tmp/boot-a/vfpu_asm/gen2.py` e `build/tmp/boot-b/vgen.py` (objdump → corpo asm, com `.word` por palavra quando nada mais serve).
- Sintaxe aceita: sem sufixo de registrador VFPU (`S000`, não `S000.s`); `li` como `addiu r, zero, imm` ou `ori` conforme o opcode (o mwcc monta `li` como `addi`); `vfim.s S030, -2.0`; condições de `vcmp` em minúsculas; `ror`/`rorv` como `rotr`/`rotrv`; `divu a, b` com dois operandos; `jalr ra, rs`; `break` só como `.word`; rótulos locais `@3c:` com `j @3c`, `jal`/`bltzal` para rótulo local; `jal símbolo` só para símbolos com protótipo no arquivo; `la r, sym+off` reproduz `lui r; addiu r, r` com relocações HI16/LO16.
- **Limite:** não há sintaxe `%hi`/`%lo` (nem `hi()`, `@ha`, `@l`) para um `lui r` seguido de `lw/lwc1 x(r)`; `lw/lwc1/sw r, sym` monta `lui $at` mesmo com `.set noat`/`.set nomacro`; `lw r, sym(base)` ignora a base (vira `0(zero)`, ou `gp` sem `-sdatathreshold 0`); `lui r, sym`, `sym@h`, `sym@ha`, `ha16()`, `hi16()`, `HI()` e o `__asm__` estilo GCC com `%hi` ou operando `"i"(&sym)` são rejeitados (testado em 2026-10-22). Essas funções ficam `@asm` com o C sob `NON_MATCHING`. Nunca use `.word` para um `lui` de endereço absoluto: o link aceita, mas a relocação some.
- Funções falsas do Ghidra (corpo de `case` de jump table separado) precisam ficar dentro do `@asm` da função mãe, senão o link falha no rótulo da jtbl.
- Renomear um `ehsys_*`/`func_*` quebra os `.c` que o chamam pelo nome antigo: `grep` em `src/` antes, ou corrija por endereço depois de um merge.

## Pendências

- `.bss`: os globais do C continuam `extern` (definidos pelo asm de `.bss`); quando um arquivo definir os próprios globais será preciso cortar a faixa correspondente do `.bss` (um `@bss` no cabeçalho, como `@data`).
- `include/` só tem o que o `ehfile` usa; crescer por subsistema.
- BOOT: todo o `.text` em C. Faltam as ~400 funções em `@asm`; na parte do SDK compilada com GCC, quase todas porque carregam dados por `lui r` + `lw/lwc1 x(r)` (ver "Código GCC como funções `asm` do mwcc").
